工程链路说明

Pixelle 从文本输入到图片生成的流程图

这页把项目里“用户文本 - LLM 规划 - 最终图片 prompt - ComfyUI 或 RunningHub 出图”的路径拆开， 方便定位每一步如何改提示词、样式规则、negative prompt、workflow 和追踪日志。

想直接看每一步产物？ 打开 文生图交互工作流观察台， 输入主题后会按现有 API 串联健康检查、narration、图片 prompt、出图和结果回溯。
2 条入口 完整标准 pipeline 与直接图片 API
多次 LLM 脚本、分镜、标题、风格、图片 prompt 等阶段
1 个媒体边界 MediaService 统一调用 workflow

两个入口

项目里有两种常见路径。第一种是完整生产链路，用户输入主题或脚本文本后， StandardPipeline 负责生成脚本、分镜、图片提示词并逐帧出图。第二种是单张图片 API， 调用方已经有最终 prompt，直接交给 /image/generate 出图。

完整文本到分镜出图

  1. input text 进入 StandardPipeline。
  2. 必要时用 LLM 生成完整脚本，再生成 storyboard plan。
  3. 每个 frame 进入 ImagePromptComposer 生成最终图片 prompt。
  4. FrameProcessor 逐帧调用 core.media。

直接单图生成

  1. POST /image/generate 接收 prompt、尺寸、workflow。
  2. 先写 final_visual_prompts.md trace。
  3. 调用 pixelle_video.media(...)。
  4. 返回 image_path，不再走脚本和 storyboard LLM。
判断依据： 如果你要改“从一段文字理解成画面”的逻辑，重点看完整 pipeline。 如果你只要改“一个最终 prompt 如何进 ComfyUI workflow”，重点看 /image/generate 和 MediaService。

LLM 交互

所有 LLM 调用最终都要经过 pixelle_video/services/llm_service.py。 这个边界要求传入 trace_context 和 trace_recorder，所以每次 LLM 请求和响应都可以被追踪。

不要只改最终 prompt： 如果画面理解偏了，通常要先看 storyboard 的 visual_goal 和 prompt_intent。 如果画风偏了，再看 style/prefix 和 final visual prompt 组装。

Prompt 组装

图片 prompt 不是一次 LLM 输出后直接送模型。当前链路会先得到 base prompt，再经过视觉计划、 供应商投影、文本策略、negative prompt 策略和 workflow 能力适配，最后才形成 provider-facing prompt。

Base prompt

generate_image_prompts 调用 image_generation.md，要求每个 frame 输出纯视觉描述。

Prompt context

ImagePromptComposer 把 frame source、visual goal、primary subject、continuity anchors 等合并给 LLM。

Final contract

FinalVisualPromptContract 保存 scene、composition、style assignment、character/world layer 和 integration priority。

Provider projection

ProviderPromptProjector 把内部 contract 投影成真正发给图片模型的文字，避免泄露内部字段名。

Negative prompt

如果 workflow 支持 negative prompt，就单独传；如果是 Z-Image 这类 positive-only，则把约束合并回正向 prompt。

snippet 
{
  "image_prompts": ["每一帧的最终图片提示词"],
  "negative_prompt": "共享负面提示词，可能为空",
  "planning_snapshot": {
    "llm_trace_refs": [],
    "final_visual_prompt_template": {},
    "storyboard_generation": {}
  },
  "prompt_plan_bundle": {
    "image_prompt_drafts": [],
    "prompt_plans": []
  }
}

媒体生成边界

真正调用图片模型的地方是 pixelle_video/services/media.py。 它先解析 workflow，再构造 workflow_params，校验 trace artifact，最后交给 core.execute_comfykit_workflow。这层是 ComfyUI 和 RunningHub 的共同边界。

media params 
media_params = {
  "prompt": frame.image_prompt,
  "workflow": config.media_workflow,
  "media_type": "image",
  "negative_prompt": frame.negative_prompt,
  "width": config.media_width,
  "height": config.media_height,
  "index": frame.index + 1,
  "media_prompt_trace_context": trace_context
}

media_result = await self.core.media(**media_params)

self-hosted workflow 通过 JSON 里的占位标题接收参数，例如默认 Z-Image workflow 的 PrimitiveStringMultiline 节点标题是 $prompt.value!， 宽高节点标题是 $width.value 和 $height.value。 RunningHub workflow 文件则是描述符，核心字段是 workflow_id 和 media_type。

修改点地图

想改什么 优先看哪里 影响范围
用户主题如何变成脚本 pixelle_video/prompts/templates/script_generation.md 影响 mode=generate 的完整 source text。
分镜数量、覆盖方式、每帧意图 storyboard_generation.md 和 StoryboardGenerationService 影响后面所有图片 prompt 的上下文。
图片 prompt 的描述结构和语言 image_generation.md 影响 base prompt，适合修正“画面该画什么”。
最终 prompt 的章节结构 final_visual_prompt.md、FinalVisualPromptContract 影响 provider-facing prompt 和 PromptPlan 记录。
画风、统一视觉语言 config.yaml 的 comfyui.image.prompt_prefix_library 或 visual profile 影响 style resolution、quality gate 和最终 prompt。
模型、采样、宽高、workflow 绑定 workflows/selfhost/*.json、config.yaml、MediaService 影响 ComfyUI 或 RunningHub 的实际执行。
日志和可回放能力 prompt_trace_artifacts.py、llm_service.py 影响 prompt trace、LLM trace 和调试闭环。

Trace 调试

调 prompt 时建议先看最终 trace，再回溯 LLM trace。最终图片不好，不一定是图片模型问题； 有可能是分镜意图、base prompt、style profile、negative prompt 或 workflow 参数在中间被改了。

最终 prompt

output/<task_id>/prompt_traces/final_visual_prompts.md，检查每帧正向和负向 prompt。

媒体调用 trace

media_prompt_traces 或每帧 prompt_traces/c*，检查 workflow、尺寸、参数 hash。

LLM trace refs

planning_snapshot.llm_trace_refs 连接脚本、分镜、prompt batch 等上游 LLM 请求。

PromptPlanBundle

查看 prompt_sections 与 final_prompt，判断是哪个 section 带偏了结果。

推荐调试顺序： 先看 final_prompt 是否表达了想要的画面，再看 prompt_sections 哪一段导致偏差； 如果最终 prompt 没问题，再检查 workflow 参数、模型和 ComfyUI 运行结果。
