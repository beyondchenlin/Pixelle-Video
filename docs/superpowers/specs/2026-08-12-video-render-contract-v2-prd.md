# Pixelle 统一视频渲染契约第二版 PRD

## 0. 文档状态

- 状态：渲染根因治理与软件资格门禁已实施；跨设备硬件发布认证尚缺英特尔快速同步编码器和视频加速接口编码器的真实设备证据，因此本需求尚未达到完整完成定义。
- 制定日期：2026-08-12。
- 适用范围：标准视频生成链路、模板物化、文字渲染、时间轴、最终音视频合成、渲染后端选择与回退。
- 当前产品决策：`hyperframes_compiled` 为稳定默认后端；`ffmpeg_manifest` 保留为实验性后端。禁止依据时长把用户明确选择的稳定后端静默切换到实验后端；长视频性能通过同一后端内的有界输入、流式处理和资源预算治理。
- 当前实现基线：新任务写入 `render_manifest.v2`；历史 `render_manifest.v1` 继续单向兼容读取。媒体矩形、连续时间轴、文字样式、单次最终编码、成品探针和固定资产摘要共同构成可复现快照。
- 取代关系：本文件取代旧设计中“`ffmpeg_manifest` 天然更快，因而可以直接成为默认后端”的产品判断。旧的模板、尺寸、文字和清单架构文档继续作为实现背景；与本文件冲突时，以本文件的产品验收标准为准。

## 1. 产品结论

Pixelle 不能把“能生成视频”作为渲染后端可默认启用的完成标准。用户购买的是可复现的最终视听结果，不是某条技术链路执行成功。

默认后端必须同时满足以下结果契约：

1. 同一任务的媒体几何、模板布局和文字排版与用户配置一致。
2. 主音频、字幕和视觉镜头共享一条连续时间轴，不丢失停顿、结尾或字幕。
3. 输出尺寸、帧率、像素格式和色彩标记固定且可验证。
4. 后端切换不重新解释字号、边距、素材尺寸、裁剪方式或镜头时长。
5. 用户显式选择的后端不会因为时长或性能估算被静默替换为另一个实验性后端。
6. 每个成品都能从任务快照中复盘实际后端、字体、几何、时间轴、编码和回退原因。

本次默认回退是生产止损，不是渲染一致性问题的最终完成状态。最终目标是让所有后端消费同一份解析完成的渲染契约。

## 2. 问题背景与事实依据

2026-08-11 与 2026-08-12 的两个同主题成功任务暴露了后端语义分裂。两者声明的输出画布均为 1280×720，字幕配置均请求 36 像素字号，但实际结果如下：

| 检查项 | 稳定后端成品 | 实验后端成品 | 结论 |
| --- | ---: | ---: | --- |
| 原始媒体尺寸 | 1280×720 | 1280×720 | 原始媒体不是缩小根因 |
| 合成后主媒体边界 | 1280×720 | 853×480 | 模板设计坐标与输出坐标重复缩放 |
| 请求字幕字号 | 36 像素 | 36 像素 | 请求一致 |
| 最终字幕字号 | 36 像素语义 | 14 像素 | 横屏错误套用竖屏缩放基准 |
| 主音频时长 | 63.540 秒 | 69.610 秒 | 两任务内容时长不同，不作为后端质量对照 |
| 最终音频时长 | 63.552 秒 | 66.688 秒 | 实验后端丢失 2.922 秒主时间轴 |
| 字幕最后结束时间 | 成品范围内 | 69.520 秒 | 实验成品在字幕结束前终止 |
| 输出平均帧率 | 30 | 29.94 | 声明帧率与实际平均帧率不一致 |
| 高清电视色彩标记 | 完整 | 缺失 | 跨播放器呈现不稳定 |

这两个任务不是严格的画风对照实验，因为镜头数、旁白、生成时间和生成资产均不同。画风变化必须通过固定脚本、固定分镜、固定原始资产的“仅重新渲染”能力验证。构图、字号和时间轴问题已经在编码前产物中复现，因果关系不依赖画风对照。

## 3. 第一性原理

最终视频结果由五个连续阶段组成：

```text
原始媒体
  -> 空间构图
  -> 文字排版
  -> 时间轴映射
  -> 音视频编码
```

每个阶段只能消费上游已经解析完成的事实，不得重新解释用户意图：

- 原始媒体阶段只负责生产或读取图片、视频和音频资产。
- 空间构图阶段只负责把资产映射到最终画布，不负责改变生成素材尺寸契约。
- 文字排版阶段只负责把统一文字样式解析为最终像素布局，不允许每个后端自行选择缩放基准。
- 时间轴阶段只负责建立从零到主时长的连续区间，不允许通过拼接语音区间删除主时间轴停顿。
- 编码阶段只负责把确定的视听帧写入目标容器，不允许修补构图、字号或时长。

由此得到核心产品原则：后端可以有不同实现，但不能拥有不同语义。

## 4. 产品目标

### 4.1 阻断级目标

1. 默认使用已经验证稳定的 `hyperframes_compiled`。
2. 禁止从稳定后端按时长静默路由到 `ffmpeg_manifest`。
3. 最终视频覆盖完整主音频与全部字幕，禁止尾部截断和累计偏移。
4. 相同渲染契约在不同后端下得到相同媒体边界和解析后文字样式。

### 4.2 质量目标

1. 最终画布和主媒体边界可通过自动探针验证。
2. 字体文件、字体家族、字号、边距、描边、换行和安全区域可复盘。
3. 输出采用恒定帧率、明确像素格式与高清电视色彩标记。
4. 最终成品只进行一次有损视频编码；中间视觉产物使用无损图片、无损帧序列或可复制的视频流。
5. 同一任务可以跳过内容生成，固定资产后重新选择后端渲染。

### 4.3 治理目标

1. 默认后端变更必须经过固定资产对照、真实成品探针和兼容回归。
2. 实验后端必须在界面和配置说明中明确标识，不能使用“最快”等未经基准测试证明的承诺。
3. 自动回退只能回退到已声明稳定且能力兼容的后端；禁止稳定后端回退到实验后端。
4. 默认切换需要独立提交，禁止与编码器重构、硬件加速或其他行为变更混在同一次提交中。

## 5. 非目标

- 本需求不改变图片生成模型、提示词、视觉角色策略和分镜生成策略。
- 本需求不删除 `legacy`、`hyperframes_compiled` 或 `ffmpeg_manifest`。
- 本需求不要求三个后端采用相同代码实现。
- 本需求不追求不同文字栅格器的逐像素完全一致；要求几何、字号、换行、字体资产和视觉阈值一致。
- 本需求不回填或重新编码历史成品。
- 本需求不以提高码率代替布局、文字和时间轴根因修复。

## 6. 用户与关键场景

### 6.1 默认生成

作为普通创作者，我希望不理解渲染技术也能直接得到稳定成品，从而避免默认选项造成画面、字幕或时长变化。

用户不选择渲染后端时，系统使用稳定默认后端。任务元数据同时记录“请求后端”和“实际后端”。只要能力满足，二者必须一致。

### 6.2 显式试用实验后端

作为高级创作者，我希望在明确知晓风险后试用实验后端，并且系统能阻止错误成品进入成功列表。

用户显式选择 `ffmpeg_manifest` 时，界面提示它处于实验状态。生成后必须运行成品契约探针；探针失败则任务标记为渲染失败并保留诊断产物，禁止把存在截断或布局错误的视频标记为成功。

### 6.3 历史任务重新渲染

作为需要复用历史作品的创作者，我希望重新渲染不会悄悄改变后端，从而保持历史任务可复现。

历史任务已有明确后端时，重新渲染继续使用该后端，除非用户明确选择新的后端。历史任务缺少后端字段时，使用当前稳定默认值。

### 6.4 固定资产后端对照

作为质量评审者，我希望固定同一批内容资产后只比较渲染结果，从而把生成随机性与后端差异分离。

用户或开发者选择一个已完成任务，冻结脚本、分镜、主音频、原始媒体、模板和文字包，只重新运行渲染阶段。系统输出两个独立成品和机器可读差异报告，禁止重新调用内容模型。

### 6.5 长视频

作为长视频创作者，我希望系统在性能保护和成品质量之间作出透明选择，而不是在任务中途无提示地改变渲染语义。

目标状态下，长视频继续使用用户请求的稳定后端。性能压力通过分块渲染、缓存、流式帧处理和资源预算解决，禁止通过不可见的后端切换规避。迁移完成前，系统保留既有的两分钟性能回退，并在任务元数据中记录实际后端与原因；该限制必须在界面可见且纳入实验后端成品探针。

## 7. 功能需求

### 7.1 后端选择契约

- 需求一：平台只维护一个运行时默认值事实源，配置模型、故事板和界面从该值派生。
- 需求二：示例配置必须与运行时默认值一致。
- 需求三：实际配置中的显式值优先于运行时默认值。
- 需求四：稳定后端不能自动回退到实验后端。
- 需求五：能力不足时只能失败并给出可操作原因，或回退到能力兼容的稳定后端。
- 需求六：请求后端、实际后端、回退原因和回退阶段必须持久化。

### 7.2 统一空间构图契约

每个视觉片段进入后端前必须解析出以下最终值：

- 输出画布宽高。
- 原始媒体宽高。
- 目标媒体矩形：横坐标、纵坐标、宽度、高度。
- 适配模式：包含、覆盖、拉伸或原始尺寸。
- 裁剪矩形。
- 圆角、遮罩、透明度和层级。
- 模板安全区域和设计坐标到输出坐标的唯一变换矩阵。

约束：

1. 模板不得通过通用图片选择器覆盖主媒体矩形。
2. 模板设计坐标到输出坐标只转换一次。
3. 后端不得重新根据文件自然尺寸推导媒体边界。
4. 合成前必须输出每个片段的解析后边界诊断。

### 7.3 统一文字契约

文字包在进入后端前必须解析出：

- 实际字体文件与字体内部家族名。
- 最终整数像素字号。
- 行高、描边、阴影、背景、颜色和透明度。
- 最终边距、安全区域、对齐方式和换行结果。
- 每条文字的开始时间和结束时间。

约束：

1. 横屏、竖屏和方屏使用显式画布基准，禁止默认使用竖屏基准处理横屏。
2. 字体路径以任务资产或应用资源解析器为准，禁止依赖进程启动目录。
3. 字体文件不存在、家族名不匹配或字形缺失时，任务在编码前失败。
4. 不同后端只能投影统一样式，不能再次缩放字号和边距。

### 7.4 连续时间轴契约

时间轴必须从零开始，连续覆盖到主时长结束。视觉片段允许在语句之间保持上一画面、切换到下一画面或使用显式过渡，但不允许删除主音频中的停顿。

约束：

1. 主旁白轨在进入最终合成时保持完整。
2. 每个视觉片段拥有连续的开始时间和结束时间。
3. 所有视觉片段合并后不得出现未定义间隙或非设计重叠。
4. 字幕时间始终基于同一主时间轴。
5. 背景音乐混合不得改变主时间轴长度。
6. 禁止逐片段编码有声视频后再拼接。

### 7.5 输出编码契约

默认输出配置：

- 视频编码：H.264。
- 像素格式：`yuv420p`。
- 帧率：每秒 30 帧恒定帧率。
- 色彩：高清电视色彩原色、转换特性和矩阵；有限范围。
- 音频：AAC，48000 赫兹，双声道。
- 有损视频编码次数：一次。

硬件编码器和软件编码器可以采用不同私有参数，但必须满足相同输出探针、色彩和感知质量门槛。硬件编码失败时允许在最终编码边界回退到软件编码，不允许重新执行构图、文字或时间轴阶段。

### 7.6 成品契约探针

任务标记成功前必须检查：

1. 文件存在且能够完整探测音视频流。
2. 输出宽高与请求画布完全一致。
3. 平均帧率与声明恒定帧率一致。
4. 像素格式和色彩标记完整。
5. 最终音频时长与主音频时长差值不超过 55 毫秒。
6. 最终视频时长覆盖字幕最大结束时间，余量不少于一帧。
7. 视觉时间轴从零连续覆盖到最终时长。
8. 实际字体文件和解析后字号与任务快照一致。
9. 有损视频编码次数不超过一次。

任一阻断项失败时，任务状态为失败，保留中间资产、探针结果和修复建议。

### 7.7 可观测与复盘

每个任务必须持久化一份渲染契约快照，至少包括：

- 契约版本。
- 请求后端、实际后端和回退原因。
- 画布与每个视觉片段的解析后媒体矩形。
- 文字样式标识、字体文件摘要、字体家族和最终字号。
- 主音频时长、字幕最大结束时间和视觉时间轴覆盖范围。
- 编码器、硬件回退、帧率、像素格式和色彩标记。
- 有损编码次数、各阶段耗时和峰值内存。
- 成品契约探针结果。

## 8. 兼容与迁移

1. 已持久化的显式 `render_backend` 保持原值。
2. 缺失 `render_backend` 的历史数据使用当前稳定默认值。
3. `hyperframes` 旧名称继续迁移为 `hyperframes_compiled`。
4. `ffmpeg_manifest` 继续可由显式配置和界面选择，不删除能力。
5. 默认回退发布后，不批量改写历史任务元数据。
6. 新契约以版本号持久化；旧任务读取时执行单向迁移，不把兼容字段继续写回新任务。
7. 重新渲染必须显示原后端与当前后端，用户确认切换后才改变。

## 9. 验收标准

### 9.1 默认与路由

- 未提供配置时，运行时、故事板和界面默认值均为 `hyperframes_compiled`。
- 示例配置默认值为 `hyperframes_compiled`。
- 121 秒和 271.910113 秒的静态任务保持 `hyperframes_compiled`，不会按时长切换到 `ffmpeg_manifest`。
- 用户显式选择 `ffmpeg_manifest` 时仍能进入该后端。

### 9.2 几何与文字

- 1280×720 原始图片放入 1280×720 全画布时，输出媒体边界为 0、0、1280、720，四边误差不超过 1 像素。
- 1920×1080 模板输出到 1280×720 时，只执行一次坐标变换。
- 横屏请求 36 像素字幕时，两个后端的解析后字号均为 36 像素。
- 字体家族、字体文件、换行行数和每行内容一致。
- 文字基线和媒体边界误差不超过 1 像素。

### 9.3 时间轴

- 主音频 69.610 秒时，最终音频时长位于 69.555 至 69.665 秒之间。
- 字幕结束于 69.520 秒时，最终视频完整覆盖该字幕并至少多一帧。
- 含镜头前停顿、镜头间停顿和尾部停顿的测试音频不得丢失任何停顿。
- 六个视觉片段共同连续覆盖从零到最终时长的全部区间。

### 9.4 编码与跨环境

- 输出为 1280×720、每秒 30 帧恒定帧率、`yuv420p` 和完整高清电视色彩标记。
- 软件编码与产品事实源声明的全部硬件编码器，即 `h264_nvenc`、`h264_qsv`、`h264_vaapi`，均必须在对应真实设备上产出最终视频并通过相同探针。
- 编译时存在编码器名称、微型运行探针通过或软件回退成功都不能替代真实设备最终视频证据。
- 跨设备聚合报告必须证明三份证据来自同一完整提交、同一次受信任构建，并分别使用请求的精确编码器；缺少任意一种编码器时发布认证失败。
- 从仓库根目录、应用安装目录和任意工作目录启动时，加载相同字体文件。
- 字幕路径包含空格、中文和特殊字符时能够安全加载，不经过命令字符串拼接。

### 9.5 性能放行

`ffmpeg_manifest` 重新申请默认后端资格时，必须在同一机器、相同固定资产和相同输出质量下分别重复运行五次：

- 中位渲染耗时不高于稳定后端的 80%。
- 峰值内存不高于稳定后端的 110%。
- 不增加有损编码次数。
- 全部质量和兼容验收先通过；性能收益不能抵消质量失败。

## 10. 测试矩阵

### 10.1 屏幕与素材

- 横屏、竖屏、方屏。
- 素材与画布同尺寸、素材小于画布、素材大于画布、素材与画布方向不同。
- 图片、静音视频、有声视频、透明叠加层。
- 包含、覆盖、拉伸和原始尺寸四种适配模式。

### 10.2 模板与文字

- 无模板、静态模板、分层模板、原生模板。
- 标题、字幕、重点文字和显式双层文字。
- 中文、英文、混排、长句、空句、特殊字符和缺失字形。
- 字号 14、36、64 与用户自定义字号。

### 10.3 时间轴

## 12. 两轮对抗式产品审查

### 12.1 第一轮：隐藏副作用与兼容性

反对意见一：“只把默认值改回去即可。”

结论：拒绝作为最终方案。真实配置可以覆盖默认值，能力解析器还会按时长静默切换后端，历史任务也会保留显式值。生产止损必须同时覆盖默认值、真实配置、隐式路由和用户说明。

反对意见二：“提高实验后端码率即可恢复画质。”

结论：拒绝。布局和字号在编码前已经错误，时间轴也在编码前被删除。码率不能恢复缺失的像素、字号和时间。

反对意见三：“现有测试全部通过，所以可以继续默认使用。”

结论：拒绝。现有测试主要验证调用和对象，没有验证真实成品。产品完成标准必须从内部实现成功升级为成品契约成功。

反对意见四：“长视频必须自动切到更快后端。”

结论：拒绝静默切换。性能属于执行策略，不能改变用户的渲染语义。长视频性能必须在同一后端内治理，或让用户显式选择经过验收的替代后端。

### 12.2 第二轮：性能、安全与未来维护成本

反对意见一：“三个后端分别适配一次更快落地。”

结论：拒绝。分别解释布局、文字和时间轴会形成三套事实源，每增加一个模板、画幅或文字属性都要进行多处同步，维护成本按后端数与功能数相乘。

反对意见二：“依赖当前工作目录寻找字体已经能运行。”

结论：拒绝。开发目录、打包目录和服务目录不同，工作目录不是资源身份。字体必须通过应用资源解析器或任务本地资产确定，并验证内部家族名。

反对意见三：“多轮编码只影响速度，不影响功能。”

结论：拒绝。多代有损编码会降低细线和文字边缘质量，硬件与软件回退还会放大不可复现性。最终有损编码必须收敛到一次。

反对意见四：“探针失败后仍可返回视频并给警告。”

结论：拒绝。截断、错误尺寸、错误字体和缺失色彩标记属于成品失败，不能以成功状态交付。失败产物可保留用于诊断，但不能进入最近成功视频列表。

安全结论：外部路径必须继续以参数数组传递给进程；模板内容和字幕内容必须分别进行上下文转义；资源解析必须限制在任务目录和受信任资源目录。任何渲染后端都不能通过拼接命令字符串处理用户输入。

## 15. 资格认证实现与证据规范

本节是需求验收的事实源，不以“代码已实现”替代真实成品证据。

### 15.1 固定资产与黄金矩阵

- 固定资产由资格工具确定性生成，源尺寸为 200×300，使用中性深灰背景、高饱和绿色外边框、青色内部矩形和品红色水平标记线。源宽高不得与任一测试画布的宽高相同，避免错误缩放被相同边长掩盖。
- 每个场景同时生成静音主音频、`render_manifest.v2` 快照、FFmpeg 成品、HyperFrames 成品、成品探针、解码帧和差异报告。
- 黄金矩阵固定为横屏、竖屏、方屏与包含、覆盖、拉伸、原始尺寸的笛卡尔积，共十二个场景。
- 媒体外边界、青色内部标记和自动换行后的两行相同测试字形必须从最终视频解码帧检测。固定期望坐标是唯一事实源；每个后端的四边和字形行底代理坐标相对固定期望的误差均不得超过一像素。后端间差值只作为诊断值，其上限由双方各自相对固定期望的误差上限推导，禁止把后端之一当作另一个后端的真值。
- 字体文件使用仓库内锁定资产；FFmpeg 适配器把统一像素字号投影为 ASS 字号单位，并按字体垂直度量投影换行步长和负半行距。旧版清单继续保留旧投影，禁止历史画面被新版规则静默改写。
- 每个场景写入独立 `difference_report.json`，总报告写入 `golden_matrix_report.json`。

执行入口：

```powershell
uv run python scripts/run_render_qualification.py golden --output-root <证据目录>
```

### 15.2 长时长、性能、历史与硬件证据

- 长时长门禁真实生成 121 秒和 271.910113 秒两个后端成品，报告为 `long_duration_report.json`。
- 性能门禁固定执行五轮并交替后端顺序，报告原始轮次、中位耗时和进程树峰值常驻内存，报告为 `performance_report.json`。
- 历史重渲染保留原模板、原媒体、原字体、原旁白与原背景音轨；相对路径只允许解析为现存原始资产，禁止静默替换，报告为 `historical_report.json`。
- 硬件编码器事实源唯一来自编码器注册表，资格工具不得另写一份容易漂移的硬编码清单。当前完整集合为 `h264_nvenc`、`h264_qsv`、`h264_vaapi`。
- 不指定编码器时，`hardware_report.json` 是单机能力发现报告；其中 `host_ok` 只表示本机可用编码器的真实成品通过，`complete_on_host` 才表示本机覆盖完整集合。单机报告的 `ok` 不得解释为跨设备发布认证完成。
- 指定 `--hardware-codec` 时，门禁只运行该精确编码器。设备不可用、真实负载失败、最终编码器发生软件回退、成品探针失败中的任意一项都会令报告失败。
- 每份精确编码器报告必须记录完整提交号、源码树清洁状态、操作系统、架构、FFmpeg 版本和构建运行号；最终视频与探针使用相对路径、文件大小和 SHA-256 摘要绑定，禁止用机器绝对路径充当可移植证据。
- 跨设备聚合器只接受同一完整提交、同一次构建运行的三份精确报告，重新验证路径边界、文件大小、摘要、单次有损编码、实际编码器字段和最终音视频探针。任一报告缺失、重复、跨提交、跨运行、被篡改或发生回退时，`hardware_certification_report.json` 必须失败。
- 英特尔快速同步编码器和视频加速接口编码器不能在无对应设备的主机上用软件模拟替代；没有真实设备就是未覆盖，而不是通过。

单机精确设备入口：

```powershell
uv run python scripts/run_render_qualification.py hardware --hardware-codec <编码器> --output-root <证据目录>
```

跨设备聚合入口：

```powershell
uv run python scripts/run_render_qualification.py hardware-certify --hardware-evidence-root <三份证据根目录> --expected-revision <完整提交号> --expected-run-id <构建运行号> --output-root <聚合证据目录>
```
