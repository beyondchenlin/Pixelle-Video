# AGENTS Git 推送默认策略设计

## 背景

当前仓库已经要求代理执行原子化暂存与原子化提交，但未明确要求提交后立即推送到 GitHub。实际协作中，这会导致本地分支持续积累大量未推送提交，增加分支状态判断、任务隔离和远端同步成本。

## 目标

为仓库补充一条明确、可执行的默认 Git 推送规则：

- 默认情况下，代理在完成一次符合原子化要求的 `git commit` 后，必须立即推送到 GitHub。
- 如果用户明确要求“只本地提交、暂不推送”，则允许该次提交不推送。

## 设计方案

仅修改仓库根目录 `AGENTS.md` 的“Git 提交与推送规则”章节，新增一条中文规则说明，不调整其他既有 Git 约束。

建议新增的规则语义如下：

- 默认每次完成原子化 `git commit` 后，必须立即执行推送到 GitHub。
- 若用户明确要求仅本地提交、暂不推送，则该次提交可以不推送。
- 若因网络、权限、远端拒绝、分支保护或其他外部条件导致无法推送，代理必须明确说明阻塞原因，不能默认视为任务完成。

## 预期效果

- 降低本地分支长期积累未推送提交的概率。
- 让“提交完成”与“远端同步完成”的默认预期保持一致。
- 保留用户对特殊场景的显式控制权，避免规则过于僵硬。

## 非目标

- 不修改仓库现有分支模型、PR 流程、CI 规则或评审规则。
- 不强制要求每次推送必须创建新分支。
- 不改变“原子化提交”的既有要求。
