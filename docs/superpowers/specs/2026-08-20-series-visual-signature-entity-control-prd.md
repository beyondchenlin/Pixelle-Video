# Pixelle 系列视觉签名文字角色安置与场景融合 PRD（产品需求文档）

## 0. 文档状态

- 制定日期：2026-08-20。
- 当前代码基线：`42ca93ba8b526d9177b9981601b8e686a9302e95`。
- 当前图片模型：Z-Image 文生图工作流。
- 最终产品产物：由分镜图片、语音、字幕、动画和音乐合成的视频。
- 本文取代同路径旧稿。旧稿中的自动成图检测、自动重试和单帧重生不再属于本需求。
- 本文只处理：文字角色进入每张分镜图片提示词时，如何保持形象一致、位置正确并自然融入场景。

## 1. 必须解决的问题

> 在生成每张分镜图时，让文字定义的 IP（角色形象）既保持一致，又能以正确的位置、大小、前后遮挡和光影关系融入画面，最终组成连贯的视频。

这里包含两个同等重要的问题：

1. **角色必须像**：同一个文字角色在不同分镜中不能变成不同外形、颜色、斑纹、服装或物种。
2. **角色必须属于画面**：角色不能像后贴的贴纸、角标或吉祥物，必须站在合理位置，与场景中的人物、物体、地面、视角和光线形成真实关系。

本需求不是成图后的检查系统，也不是重新生成流程。

## 2. 当前代码事实与根因

| 事实 | 当前情况 | 造成的问题 |
| --- | --- | --- |
| 角色来源 | 系列视觉签名已经保存固定名称和身份特征 | 角色形象已经有唯一文字来源，应继续复用 |
| 每帧投影 | 第4.5版投影服务负责把角色写入最终提示词 | 主链正确，不应新建第二套角色链路 |
| 当前角色条款 | 只要求角色与某个真实元素、道具、表面或动作绑定 | 具体绑在哪里、占多大、在谁前后仍交给图片模型猜测 |
| 已含角色的快捷路径 | 基础提示词已出现身份特征时，会保留原提示词 | 该路径可以绕过明确的安置和融合条款 |
| 当前模型能力 | Z-Image 工作流只接收正向和负向文字提示词 | 当前不能把方框、遮罩、深度图或姿态图伪装成已支持能力 |
| 最终产物 | 分镜图片继续进入语音、字幕和视频合成 | 单张图片中的突兀角色会在最终视频中连续暴露 |

根因不是角色文字缺失，而是当前合同只表达了“它是谁”，没有完整表达“它在本帧哪里、做什么、与场景如何发生关系”。

## 3. 产品目标

### 3.1 阻断级目标

1. 每张启用系列视觉签名的分镜，在调用图片模型前都必须同时拥有角色身份合同、安置计划和场景融合计划。
2. 固定角色身份特征必须逐帧使用同一份规范化文字，不允许每帧重新概括或改写角色外形；任何景别都必须保留核心识别特征。
3. 每帧必须明确角色的数量、位置、大小、前后景、动作、关联对象和支撑面。
4. 每帧必须明确适用于该画面类型的遮挡、透视、光线、阴影和画面风格关系；抽象图不适用的物理关系必须明确标记为不适用，不能虚构地面或阴影。
5. 上游要求出现的主体不能被角色替代、遮住或挤出主要构图。
6. 已经包含角色身份特征的基础提示词，也必须补齐同一份安置和融合条款。

### 3.2 质量目标

1. 角色在系列分镜中保持同一身份，但动作、朝向和姿势可以随场景变化。
2. 角色优先使用画面中已有的地面、道路、桌面、座椅、门口或其他合理空间。
3. 角色的大小服从本帧叙事作用，不能默认居中、放大或抢占主主体。
4. 角色必须继承整张图的画风、镜头视角、光源方向和阴影软硬。
5. 最终提示词必须使用明确事实，禁止继续使用“自然融入”“绑定某物”这类未完成决策的泛化表达。

### 3.3 非目标

- 不增加自动成图检测、自动评分或自动验收。
- 不增加自动重试、单帧重生或并发重生机制。
- 不要求用户画框、画遮罩或手工指定角色位置。
- 不使用参考图生成角色，角色继续完全由文字定义。
- 不训练或微调新的基础图片模型。
- 不承诺当前纯文字工作流具备像素级精确定位能力。
- 不改造现有视频合成、语音、字幕和最终结果查看流程。

## 4. 核心设计

角色描述必须拆成两层，不能混成一段自由文本。

### 4.1 跨分镜固定身份

固定身份是整个系列共享的唯一角色事实，至少包含：

- 角色名称。
- 物种或角色类型。
- 体型和身体比例。
- 主色和辅色。
- 稳定斑纹、脸部、毛发或轮廓特征。
- 固定服装、配饰和标志性物件。
- 必须保留的识别特征。
- 禁止出现的错误特征。

固定身份必须进一步拆成：

- `core_identity_traits`：非空核心识别特征。任何分镜、任何景别都必须保留，用于证明它仍是同一个角色。
- `supporting_identity_traits`：补充外形细节。与核心特征一起按稳定顺序编入规范身份文字，整份规范身份文字必须满足四百字符预算。
- `canonical_identity_clause`：由上述特征确定性编译出的唯一规范文字，当前 Z-Image 正向提示词中的长度上限为四百个字符。
- `identity_content_sha256`：根据规范化名称、核心特征、补充特征和禁止特征计算的内容散列，作为本次任务使用的不可变身份版本。

固定身份一旦进入本次视频生成任务，所有分镜必须使用同一个角色档案标识和同一个身份内容散列，不允许某一帧自行增删或同义改写关键特征。规范身份文字超过四百个字符时，角色档案在进入生成流程前失败，不能在最终编译时静默截断。

### 4.2 每帧可变表达

每帧只允许改变与当前场景有关的内容：

- 动作和姿势。
- 表情和视线。
- 身体朝向。
- 与主主体的互动方式。
- 在画面中的位置和大小。
- 本帧实际可见的身体范围。

可变表达不能修改固定身份。全身、半身、局部和远景都必须保证核心识别特征与当前朝向、遮挡和可见范围相容；无法展示核心识别特征的安置候选不能进入最终合同。

### 4.3 每帧安置计划

每帧安置计划至少包含：

| 信息 | 必须回答的问题 |
| --- | --- |
| 数量 | 本帧出现几个该角色 |
| 水平位置 | 左侧、中间还是右侧 |
| 景深位置 | 前景、中景还是背景 |
| 相对大小 | 小、中小、中等还是大 |
| 关联对象 | 角色与哪个人物、物体或场景区域发生关系 |
| 空间关系 | 在关联对象前方、后方、旁边、下方还是内部 |
| 支撑面 | 角色站、坐、趴或依附在哪个已有表面上 |
| 动作 | 角色在本帧具体做什么 |
| 朝向 | 面向镜头、背向镜头或朝向哪个主体 |
| 可见范围 | 全身、半身、局部还是远景轮廓 |

不再把百分之二、百分之四这类数字直接写给图片模型。产品合同新增“小、中小、中等、大”四档相对大小，再由不同模型适配器转换为适合该模型的文字。

现有 `max_area_ratio` 暂时保留为内部安全上限和旧请求兼容字段，但不能继续直接编译成 Z-Image 提示词。首次迁移使用固定映射：不超过百分之十为小，大于百分之十且不超过百分之十八为中小，大于百分之十八且不超过百分之三十为中等，大于百分之三十且不超过百分之四十五为大。新合同以相对大小为主要生成事实，内部上限只负责约束相对大小不能放大越界。

### 4.4 角色类型边界

文字角色必须始终保持角色形态，不能为了适应画面被转换成符号或容器。

- 允许自动选择：核心参与、安静旁观、操作和引导。
- 禁止自动选择：障碍物、容器和背景标记，因为这些类型会把角色改造成物体、结构或符号。
- 旧请求显式选择禁止类型时，生成前返回明确的角色类型不兼容错误，不允许静默改成其他类型。
- 自动角色解析只能从允许类型中选择，并且选择结果必须支持核心识别特征在本帧可见。

### 4.5 每帧场景融合计划

“自然融入”必须拆成可执行事实：

| 信息 | 必须回答的问题 |
| --- | --- |
| 遮挡关系 | 谁挡住谁，允许遮挡到什么程度 |
| 透视关系 | 角色是否与同一地面、道路或室内空间使用一致透视 |
| 接触关系 | 脚、身体或物件如何接触支撑面，不能悬空 |
| 光线关系 | 角色接受哪一方向、颜色和强度的主光 |
| 阴影关系 | 阴影落在哪里，软硬和场景是否一致 |
| 风格关系 | 角色使用与整张图相同的线条、材质、颗粒和真实程度 |
| 主体保护 | 角色不能遮挡、替代或弱化哪些上游必需主体 |
| 禁止构图 | 不得出现贴纸、角标、徽章、独立展示台或无关承载物 |

物理场景必须填写接触、透视、光线和阴影；流程图、结构图和关系图只填写实际存在的图形层级、遮挡和风格关系，其余物理字段明确标记为不适用。

## 5. 目标生成流程

```text
文章与分镜上下文
  -> 基础视觉简报
  -> 系列角色固定身份
  -> 本帧角色作用
  -> 本帧安置计划
  -> 本帧场景融合计划
  -> 第4.5版最终视觉合同
  -> 最终正向与负向提示词
  -> Z-Image 图片生成
  -> 现有分镜处理与视频合成
```

图片生成之后不增加新的自动检查或自动处理步骤。

## 6. 功能需求

### 6.1 固定身份投影

1. 第4.5版投影服务继续是系列角色身份的唯一生产入口。
2. 每个启用帧必须引用同一个角色档案标识和同一个身份内容散列。
3. 最终正向提示词必须完整保留规范身份文字，且核心识别特征不得缺失。
4. 规范身份文字属于受保护内容，超过四百个字符时必须在角色档案进入生成前失败，不能在最终编译阶段截断。
5. 基础提示词已经含有角色描述时，只能避免重复，不能跳过安置和融合编译。
6. 不得从文章、分镜或模型自由输出中创建第二份冲突角色描述。

### 6.2 安置规划

1. 安置规划只读取当前已有的分镜上下文、基础视觉简报、文章具象化结果、必需主体和角色身份。
2. 先保护本帧主主体和核心叙事动作，再决定角色位置。
3. 优先选择与本帧内容有自然关系的已有主体、已有物体或已有空间。
4. 角色位置必须同时包含水平位置和前后景，不能只写“在旁边”。
5. 角色大小必须使用相对画面尺度，且服从本帧角色作用。
6. 角色必须引用已有支撑面，禁止为了安置角色凭空增加台子、牌子、盒子或舞台。
7. 当前场景缺少明确互动关系时，按画面类型使用固定保守方案：
   - 真实或插画场景：角色位于画面边缘的中景，使用中小尺度，落在已有地面、道路、座椅或其他合理表面上，不遮挡主主体。
   - 流程图、结构图或关系图：角色以小型操作员或引导者身份靠近已有节点、路径或容器，使用与图表一致的线条和材质，不虚构地面、透视阴影或展示台。
   - 保守方案仍无法展示核心识别特征时，本帧合同在调用图片模型前失败，不能把角色缩成无法识别的背景小点。

### 6.3 场景融合规划

1. 角色和主主体处于同一空间时，必须使用一致的镜头高度、透视方向和地面关系。
2. 角色接触地面或物体时，必须写明接触点和接触阴影。
3. 场景存在明确光源时，必须把光源方向、色温和阴影方向写入角色条款。
4. 场景存在前景遮挡物时，允许角色被自然局部遮挡，但不能失去本帧要求展示的核心身份特征。
5. 画面为插画、线稿、矢量图或写实时，角色必须使用相同表现方式，不能单独变成另一种画风。
6. 融合计划不能改变文章要求的主体、关系和主要构图。

### 6.4 最终提示词编译

最终正向提示词按以下顺序组织：

1. 本帧主要内容和主主体。
2. 系列角色固定身份。
3. 角色在本帧的动作和作用。
4. 角色的位置、大小、前后景、关联对象和支撑面。
5. 遮挡、透视、光线、阴影和风格融合关系。
6. 主主体保护和其他不可违反的限制。

最终负向提示词至少排除：

- 角色重复或出现额外同类角色。
- 角色变成贴纸、角标、徽章、标志或水印。
- 角色悬空、漂浮或没有接触关系。
- 角色使用与场景不同的画风、光线或透视。
- 角色默认居中、过大或遮挡主主体。
- 为角色新增无关展示台、牌子、盒子或舞台。
- 固定身份中的禁止特征。

当前 Z-Image 提示词预算固定如下：

| 内容 | 正向提示词预算 |
| --- | ---: |
| 本帧主要内容和必需主体 | 四百个字符 |
| 规范身份文字 | 四百个字符 |
| 安置和场景融合 | 三百个字符 |
| 画面风格 | 一百个字符 |

正向提示词总长度不得超过一千二百个字符，负向提示词不得超过八百个字符。规范身份、必需主体、安置和融合都属于受保护事实；任何受保护部分超过自己的预算时，必须在调用图片模型前返回明确错误，禁止静默截断。补充身份细节和装饰性风格只能使用剩余预算。

各段预算包含段间分隔符和编译器加入的固定句式，四段编译后的总长度必须再次执行一千二百字符总门禁。

### 6.5 模型适配

1. 最终视觉合同保持模型无关，不能把 Z-Image 专用文字写入事实模型。
2. 当前 Z-Image 适配器只消费正向提示词和负向提示词。
3. 当前工作流没有声明方框、遮罩、深度或姿态能力时，系统不得发送或假装使用这些能力。
4. 未来接入 OpenAI 图片模型时，继续消费同一份身份、安置和融合合同，再由新的模型适配器转换请求。
5. 未来模型拥有更强区域控制能力时，属于单独需求，不反向污染当前文字合同。
6. 当前 `max_area_ratio` 只用于内部安全上限和旧请求兼容；Z-Image 适配器只发送由该上限约束后的相对大小文字，不发送面积百分比。

### 6.6 保存与追踪

每帧必须保存：

- 角色档案标识和身份内容散列。
- 本帧安置计划。
- 本帧场景融合计划。
- 最终正向提示词。
- 最终负向提示词。
- 合同版本和内容散列。

现有 `PromptPlan` 只保存最终正向提示词，本次必须新增可选的 `final_negative_prompt` 兼容字段；旧记录允许为空，新生成的第4.5版系列视觉签名记录必须保存实际发送的最终负向提示词。保存这些信息只用于复现和排查提示词，不保存自动成图检测结果。

### 6.7 用户流程

本需求不增加新的用户操作。

- 用户仍按现有方式一次性运行完整视频生成流程。
- 系统在生成每张分镜图前自动完成角色安置和场景融合规划。
- 用户仍在流程完成后查看最终结果。
- 本文不定义用户查看结果后的处理动作。

## 7. 六帧斑点狗案例

六帧使用同一份斑点狗固定身份文字。每帧只改变动作、位置和场景关系。

1. 第一帧：斑点狗必须落在已有地面或道路上，与场景透视和光线一致。
2. 第二帧：只出现一只斑点狗，不能因提示词重复投影而生成两只。
3. 第三帧：斑点狗与人物和已有地面形成明确关系，不能像后贴吉祥物。
4. 第四帧：斑点狗服从本帧的次要角色作用，不能放大后抢占主体。
5. 第五帧：斑点狗不能替代或遮挡特斯拉、电动汽车或行业变革等上游必需主体。
6. 第六帧：斑点狗可以与人物自然同行，动作、朝向、脚下接触和投影必须与人物所在空间一致。

## 9. 验收标准

### 9.1 自动化合同验收

1. 启用系列视觉签名时，每帧身份、安置和融合合同覆盖率为百分之百。
2. 每帧最终正向提示词包含同一个身份内容散列对应的规范身份文字，核心识别特征完整保留。
3. 每帧最终正向提示词包含位置、前后景、大小、关联对象、支撑面和动作。
4. 每帧最终正向提示词包含适用的遮挡、透视、光线、阴影和风格关系。
5. 已含身份特征的基础提示词路径同样包含完整安置和融合条款。
6. 必需主体在最终合同和最终提示词中的保留率为百分之百。
7. 不支持区域控制的工作流不会收到方框、遮罩、深度图或姿态图参数。
8. 生成链中不会调用图片分析、自动验收或自动重试服务。
9. 自动角色解析不会产生障碍物、容器和背景标记类型；显式请求这些类型会在生成前失败。
10. 真实场景和抽象图分别使用各自的保守回退，且回退后核心识别特征仍可见。
11. 最终正向提示词不超过一千二百个字符，最终负向提示词不超过八百个字符；受保护事实不会被截断。
12. 旧面积上限能够稳定映射为相对大小，Z-Image 最终提示词不出现面积百分比。
13. 新生成的第4.5版提示词计划同时保存最终正向和负向提示词，旧记录继续可读。

### 9.2 固定样本人工验收

人工验收只用于开发和发布验证，不进入用户运行流程。

1. 使用固定角色文字、固定六帧脚本、固定模型文件散列、固定工作流文件散列、固定采样参数、固定尺寸和固定随机种子，对比改造前后结果。
2. 逐帧检查角色身份、位置大小、主体关系、落地接触、遮挡、透视、光线和画风。
3. 六帧最终提示词必须全部通过合同检查。
4. 六帧成图不得出现角色身份突变、重复角色、贴纸化、悬空、独立展示台或严重遮挡主主体。
5. 六帧合成视频中，角色应被观看者识别为同一角色，并属于各自场景，而不是六次独立粘贴。

## 11. 泼冷水结论

1. 纯文字文生图只能提高位置和融合的稳定性，不能提供像素级硬约束；文档不能把文字合同包装成方框或遮罩能力。
2. “保持角色一致”不能只重复角色名字，必须逐帧复用完整固定身份特征。
3. “自然融入”不是可执行要求，必须拆成支撑面、遮挡、透视、光线、阴影和画风。
4. 百分比面积对当前文字模型属于虚假精度，应改用相对大小和明确构图关系。
5. 负向提示词只能减少错误，不能替代正向提示词中的具体位置和物理关系。
6. 未来图片模型支持更强区域能力时，可以提升控制精度，但当前合同必须先把角色和场景关系表达完整。

## 12. 完成定义

- 第4.5版投影仍是系列角色身份、安置和融合的唯一入口。
- 每张启用帧都有固定身份、身份内容散列、每帧安置和场景融合合同。
- 文字角色只使用保持角色形态的允许角色类型，任何景别都保留核心识别特征。
- 最终提示词完整回答“它是谁、在哪里、占多大、与谁发生关系、如何站住、如何受光”。
- 已含角色身份的提示词不能绕过安置和融合编译。
- 当前 Z-Image 工作流只接收真实支持的文字能力。
- 当前 Z-Image 最终正向和负向提示词满足确定预算，且实际发送内容可以完整复现。
- 用户运行流程中没有新增自动检测、自动验收或自动重试。
- 六帧斑点狗样本和相关自动化测试全部通过。
- 文档、合同、编译器、提示词追踪和测试使用同一组事实字段。
