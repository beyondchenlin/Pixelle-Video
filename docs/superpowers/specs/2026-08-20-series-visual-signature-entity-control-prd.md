# Pixelle 系列视觉签名文字角色安置与场景融合 PRD（产品需求文档）

## 0. 文档状态

- 制定日期：2026-08-20。
- 当前代码基线：`88e709f2c1fa571f219b3942148975f9f56bcb7b`。
- 当前图片模型：Z-Image 文生图工作流。
- 最终产品产物：由分镜图片、语音、字幕、动画和音乐合成的视频。
- 本文取代同路径旧稿。旧稿中的自动成图检测、自动重试和单帧重生不再属于本需求。
- 本文只处理：文字角色进入每张分镜图片提示词时，如何保持形象一致、位置正确并自然融入场景。

## 1. 必须解决的问题

> 在生成每张分镜图时，让文字定义的 IP（角色形象）既保持一致，又能以正确的位置、大小、前后遮挡和光影关系融入画面，最终组成连贯的视频。

这里包含两个同等重要的问题：

1. **角色必须像**：同一个文字角色在不同分镜中不能变成不同外形、颜色、斑纹、服装或物种。
2. **角色必须属于画面**：角色不能像后贴的贴纸、角标或吉祥物，必须站在合理位置，与场景中的人物、物体、地面、视角和光线形成真实关系。

本需求不是成图后的检查系统，也不是重新生成流程。

## 2. 当前代码事实与根因

| 事实 | 当前情况 | 造成的问题 |
| --- | --- | --- |
| 角色来源 | 系列视觉签名已经从资产档案构建一次规范化角色快照，并在所有分镜复用名称和身份特征 | 单任务内已经有唯一角色来源，应扩展现有快照，不能新建第二套角色链路 |
| 旧身份字段投影 | 当前第4.5版快照按 `identity_lock`、`minimal_traits`、`identity_anchors` 顺序只取第一组非空字段 | 角色档案同时填写多组身份事实时，后续字段会被静默忽略，导致现有身份信息丢失 |
| 每帧投影 | 第4.5版投影服务已经是最终角色提示词的唯一生产入口 | 主链所有权正确，本需求应在该入口补齐合同，而不是旁路追加提示词 |
| 当前角色合同 | 只有角色档案、角色作用、面积上限、通用参与规则和通用风格规则 | 没有每帧位置、景深、相对大小、关联对象、支撑关系、遮挡、透视和光影事实 |
| 已含角色的快捷路径 | 基础提示词包含全部身份特征时，代码直接保留原提示词，只修补缺失名称和必需主体；负向提示词只补通用保护词 | 该路径会绕过角色作用、面积限制、安置、融合、正向提示词最终长度门禁和角色档案中的禁止特征 |
| 角色类型 | 当前合同仍接受障碍物、容器和背景标记 | 显式请求可以把文字角色改造成物体、结构或符号 |
| 提示词预算 | 普通编译路径限制正向提示词一千二百字符，但保留原提示词路径允许最长两万字符；负向提示词八百字符限制只存在于 Z-Image 专用对象 | 真实生产投影使用通用提示词对象，正负向最终长度门禁没有覆盖所有实际调用路径 |
| 提示词门禁 | 当前只检查必需主体、角色名称、全部身份特征，以及贴纸、标志、水印、重复角色等负向保护词 | 缺少角色作用、相对大小、安置和融合检查，仍会把不完整提示词记为门禁通过 |
| 保存与复现 | 每帧生成对象可以携带负向提示词，追踪工件也能记录正负向提示词，但 `PromptPlan` 只保存最终正向提示词 | 提示词计划记录无法独立复现实际发送的正负向请求，也没有身份内容散列和合同内容散列 |
| 提示词分段 | 投影服务替换最终正负向提示词时继续保留投影前的 `prompt_contract`，提示词计划再从旧合同生成 `prompt_sections` | `final_prompt` 已经包含角色投影结果，但结构化分段仍描述投影前内容，记录内部不一致 |
| 当前模型能力 | Z-Image 工作流只接收正向和负向文字提示词 | 当前不能把方框、遮罩、深度图或姿态图伪装成已支持能力 |
| 最终产物 | 分镜图片继续进入语音、字幕和视频合成 | 单张图片中的突兀角色会在最终视频中连续暴露 |

根因包含两层：一是当前合同只完整表达“它是谁”，没有完整表达“它在本帧哪里、做什么、与场景如何发生关系”；二是当前主链存在快捷路径和适配器门禁脱节，即使普通编译器具备部分限制，实际发送路径仍能绕过这些限制。

## 3. 产品目标

### 3.1 阻断级目标

1. 每张启用系列视觉签名的分镜，在调用图片模型前都必须同时拥有角色身份合同、安置计划和场景融合计划。
2. 固定角色身份特征必须逐帧使用同一份规范化文字，不允许每帧重新概括或改写角色外形；规范身份文字在任何景别都保留全部核心识别特征，本帧画面展示与视角相容且足以识别角色的核心特征子集。
3. 每帧必须明确角色的数量、位置、大小、前后景、动作、关联对象和支撑关系。
4. 每帧必须明确适用于该画面类型的遮挡、透视、光线、阴影和画面风格关系；抽象图不适用的物理关系必须明确标记为不适用，不能虚构地面或阴影。
5. 上游要求出现的主体不能被角色替代、遮住或挤出主要构图。
6. 已经包含角色身份特征的基础提示词，也必须补齐同一份安置和融合条款。
7. 普通编译路径、已含角色的输入路径和 Z-Image 实际发送路径必须执行同一套最终正负向提示词预算门禁，任何路径不得直接发布未经过适配器验证的通用提示词对象。
8. 每帧实际发送的最终正向提示词、最终负向提示词、身份内容散列、合同内容散列和合同版本必须能够一起保存和复现。

### 3.2 质量目标

1. 角色在系列分镜中保持同一身份，但动作、朝向和姿势可以随场景变化。
2. 角色优先使用画面中已有的地面、道路、桌面、座椅、门口或其他合理空间。
3. 角色的大小服从本帧叙事作用，不能默认居中、放大或抢占主主体。
4. 角色必须继承整张图的画风，以及本帧实际存在的镜头视角、光源方向和阴影软硬；抽象图不虚构物理关系。
5. 最终提示词必须使用明确事实，禁止继续使用“自然融入”“绑定某物”这类未完成决策的泛化表达。
6. 门禁通过只能表示本帧身份、必需主体、安置、融合、预算和模型能力合同全部完整，不能用“已包含角色文字”代替完整合同检查。

### 3.3 非目标

- 不增加自动成图检测、自动评分或自动验收。
- 不增加自动重试、单帧重生或并发重生机制。
- 不要求用户画框、画遮罩或手工指定角色位置。
- 不使用参考图生成角色，角色继续完全由文字定义。
- 不训练或微调新的基础图片模型。
- 不承诺当前纯文字工作流具备像素级精确定位能力。
- 不改造现有视频合成、语音、字幕和最终结果查看流程。

## 4. 核心设计

角色描述必须拆成两层，不能混成一段自由文本。

### 4.1 跨分镜固定身份

固定身份是整个系列共享的唯一角色事实，至少包含：

- 角色名称。
- 物种或角色类型。
- 体型和身体比例。
- 主色和辅色。
- 稳定斑纹、脸部、毛发或轮廓特征。
- 固定服装、配饰和标志性物件。
- 必须保留的识别特征。
- 禁止出现的错误特征。

固定身份必须进一步拆成：

- `core_identity_traits`：非空核心识别特征。完整列表必须逐帧进入规范身份文字，不能因景别变化被删除或改写。
- `supporting_identity_traits`：补充外形细节。与核心特征一起按稳定顺序编入规范身份文字。
- `canonical_identity_clause`：由名称、核心特征和补充特征确定性编译出的唯一规范文字；四百字符预算必须包含名称、固定句式、分隔符和全部身份特征。
- `identity_content_sha256`：对规范化名称、核心特征、补充特征和禁止特征的固定键序 JSON 执行 UTF-8 编码和 SHA-256 计算得到。字符串统一去除首尾空白、折叠连续空白并执行 Unicode NFC 规范化；数组保留规范身份文字中的稳定顺序。

固定身份一旦进入本次视频生成任务，所有分镜必须使用同一个角色档案标识、同一个身份内容散列和逐字相同的规范身份文字，不允许某一帧自行增删或同义改写关键特征。规范身份文字超过四百个字符时，角色档案在进入生成流程前失败，不能等到逐帧编译时才失败，也不能静默截断。

现有资产档案不新增用户必填字段，按以下固定顺序迁移：

1. `core_identity_traits` 由 `identity_lock` 后接 `minimal_traits` 合并、规范化和去重得到。
2. 两者都为空时，使用 `identity_anchors` 作为核心识别特征；三者都为空时保持当前生成前失败行为。
3. `supporting_identity_traits` 使用尚未进入核心特征的 `identity_anchors`。
4. 禁止特征继续来自 `forbidden_elements`。
5. 合并和去重必须保留首次出现顺序，不能继续使用“第一组非空字段覆盖其余字段”的逻辑。

### 4.2 每帧可变表达

每帧只允许改变与当前场景有关的内容：

- 动作和姿势。
- 表情和视线。
- 身体朝向。
- 与主主体的互动方式。
- 在画面中的位置和大小。
- 本帧实际可见的身体范围。
- 本帧在当前朝向、遮挡和景别下能够看见的核心识别特征。

可变表达不能修改固定身份。规范身份文字始终包含全部核心识别特征，但本帧可见核心特征必须与当前朝向、遮挡和可见范围一致。例如背影视角不能声称看见只存在于正脸的特征。每帧至少要展示足以识别该角色的一组核心特征；完全无法展示任何核心识别特征的安置候选不能进入最终合同。

### 4.3 每帧安置计划

每帧安置计划至少包含：

| 信息 | 必须回答的问题 |
| --- | --- |
| 画面类型 | 物理场景还是抽象图 |
| 数量 | 本帧出现几个该角色；当前单角色档案固定为一个实例 |
| 水平位置 | 左侧、中间还是右侧 |
| 景深位置 | 前景、中景还是背景 |
| 相对大小 | 小、中小、中等还是大 |
| 关联对象 | 角色与哪个人物、物体或场景区域发生关系 |
| 空间关系 | 在关联对象前方、后方、旁边、下方还是内部 |
| 支撑关系 | 物理场景写明角色站、坐、趴或依附在哪个已有表面；抽象图写明角色靠近、指向或操作哪个已有节点、路径或容器 |
| 动作 | 角色在本帧具体做什么 |
| 朝向 | 面向镜头、背向镜头或朝向哪个主体 |
| 可见范围 | 全身、半身、局部还是远景轮廓 |
| 可见核心特征 | 当前朝向、遮挡和景别下实际能够展示哪些核心识别特征 |

当前一个角色档案在一帧中固定只生成一个实例；多角色或同一角色多实例属于独立需求。安置规划器必须先确定画面类型，再验证必填字段：物理场景不能缺少真实支撑面，抽象图不能虚构地面、接触阴影和物理透视。

不再把百分之二、百分之四这类数字直接写给图片模型。产品合同新增“小、中小、中等、大”四档相对大小，再由不同模型适配器转换为适合该模型的文字。

现有 `max_area_ratio` 暂时保留为内部安全上限和旧请求兼容字段，但不能继续直接编译成 Z-Image 提示词。首次迁移使用固定映射：不超过百分之十为小，大于百分之十且不超过百分之十八为中小，大于百分之十八且不超过百分之三十为中等，大于百分之三十且不超过百分之四十五为大。新合同以相对大小为主要生成事实，内部上限只负责约束相对大小不能放大越界。

### 4.4 角色类型边界

文字角色必须始终保持角色形态，不能为了适应画面被转换成符号或容器。

- 允许自动选择：核心参与、安静旁观、操作和引导。
- 禁止自动选择：障碍物、容器和背景标记，因为这些类型会把角色改造成物体、结构或符号。
- 旧请求显式选择禁止类型时，生成前返回明确的角色类型不兼容错误，不允许静默改成其他类型。
- 自动角色解析只能从允许类型中选择，并且选择结果必须支持核心识别特征在本帧可见。

### 4.5 每帧场景融合计划

“自然融入”必须拆成可执行事实：

| 信息 | 必须回答的问题 |
| --- | --- |
| 遮挡关系 | 谁挡住谁，允许遮挡到什么程度 |
| 透视关系 | 角色是否与同一地面、道路或室内空间使用一致透视 |
| 接触关系 | 脚、身体或物件如何接触支撑面，不能悬空 |
| 光线关系 | 角色接受哪一方向、颜色和强度的主光 |
| 阴影关系 | 阴影落在哪里，软硬和场景是否一致 |
| 风格关系 | 角色使用与整张图相同的线条、材质、颗粒和真实程度 |
| 主体保护 | 角色不能遮挡、替代或弱化哪些上游必需主体 |
| 禁止构图 | 不得出现贴纸、角标、徽章、独立展示台或无关承载物 |

物理场景必须填写接触、透视、光线和阴影；流程图、结构图和关系图只填写实际存在的图形层级、遮挡和风格关系，其余物理字段在结构化合同中标记为 `not_applicable`。编译器必须省略这些不适用字段，不能把“无地面”“无阴影”或“不适用”当成画面内容写进正向提示词。

## 5. 目标生成流程

```text
文章与分镜上下文
  -> 基础视觉简报
  -> 系列角色固定身份
  -> 身份规范文字与内容散列预检
  -> 本帧角色作用
  -> 本帧安置计划
  -> 本帧场景融合计划
  -> 第4.5版最终视觉合同
  -> 最终正向与负向提示词
  -> 合同完整性与提示词预算门禁
  -> Z-Image 模型适配器
  -> Z-Image 图片生成
  -> 现有分镜处理与视频合成
```

已含角色身份的基础提示词也必须从“本帧角色作用”继续经过同一流程，只能在规范身份文字编译时去重，不能直接发布原提示词。图片生成之后不增加新的自动检查或自动处理步骤。

## 6. 功能需求

### 6.1 固定身份投影

1. 第4.5版投影服务继续是系列角色身份的唯一生产入口。
2. 每个启用帧必须引用同一个角色档案标识和同一个身份内容散列。
3. 最终正向提示词必须完整保留规范身份文字，且核心识别特征不得缺失。
4. 规范身份文字属于受保护内容，超过四百个字符时必须在角色档案进入生成前失败，不能在最终编译阶段截断。
5. 基础提示词已经含有角色描述时，只能避免重复，不能跳过安置和融合编译。
6. 不得从文章、分镜或模型自由输出中创建第二份冲突角色描述。
7. 同一规范化身份输入必须生成逐字相同的规范身份文字和身份内容散列；名称、任一身份特征或禁止特征变化时，身份内容散列必须变化。
8. 现有资产档案中的 `identity_lock`、`minimal_traits` 和 `identity_anchors` 必须按4.1节规则合并，任何非空身份字段都不能被静默丢弃。

### 6.2 安置规划

1. 安置规划只读取当前已有的分镜上下文、基础视觉简报、文章具象化结果、必需主体和角色身份。
2. 先保护本帧主主体和核心叙事动作，再决定角色位置。
3. 优先选择与本帧内容有自然关系的已有主体、已有物体或已有空间。
4. 角色位置必须同时包含水平位置和前后景，不能只写“在旁边”。
5. 角色大小必须使用相对画面尺度，且服从本帧角色作用。
6. 物理场景必须引用已有支撑面，抽象图必须引用已有节点、路径或容器；禁止为了安置角色凭空增加台子、牌子、盒子或舞台。
7. 当前场景缺少明确互动关系时，按画面类型使用固定保守方案：
   - 真实或插画场景：角色位于画面边缘的中景，使用中小尺度，落在已有地面、道路、座椅或其他合理表面上，不遮挡主主体。
   - 流程图、结构图或关系图：角色以小型操作员或引导者身份靠近已有节点、路径或容器，使用与图表一致的线条和材质，不虚构地面、透视阴影或展示台。
   - 保守方案仍无法展示核心识别特征时，本帧合同在调用图片模型前失败，不能把角色缩成无法识别的背景小点。
8. 安置规划器必须返回稳定、可序列化的结构化结果；画面类型、数量、位置、景深、相对大小、关联对象、支撑关系、动作、朝向、可见范围或可见核心特征缺失时，必须在调用图片模型前返回带帧标识和字段路径的明确错误。

### 6.3 场景融合规划

1. 角色和主主体处于同一空间时，必须使用一致的镜头高度、透视方向和地面关系。
2. 角色接触地面或物体时，必须写明接触点和接触阴影。
3. 场景存在明确光源时，必须把光源方向、色温和阴影方向写入角色条款。
4. 场景存在前景遮挡物时，允许角色被自然局部遮挡，但不能失去本帧要求展示的核心身份特征。
5. 画面为插画、线稿、矢量图或写实时，角色必须使用相同表现方式，不能单独变成另一种画风。
6. 融合计划不能改变文章要求的主体、关系和主要构图。
7. 融合规划器必须输出结构化字段，禁止只返回“自然融入”“与场景一致”或“绑定某物”等未完成决策的自由文本。

### 6.4 最终提示词编译

最终正向提示词按以下顺序组织：

1. 本帧主要内容和主主体。
2. 系列角色固定身份。
3. 角色在本帧的动作和作用。
4. 角色的位置、大小、前后景、关联对象和支撑关系。
5. 遮挡、透视、光线、阴影和风格融合关系。
6. 主主体保护和其他不可违反的限制。

最终负向提示词至少排除：

- 角色重复或出现额外同类角色。
- 角色变成贴纸、角标、徽章、标志或水印。
- 角色悬空、漂浮或没有接触关系。
- 角色使用与场景不同的画风、光线或透视。
- 角色默认居中、过大或遮挡主主体。
- 为角色新增无关展示台、牌子、盒子或舞台。
- 固定身份中的禁止特征。

上述负向保护在普通编译、已含身份输入和旧请求兼容路径中必须逐项一致；最终门禁必须检查角色档案中的每一条禁止特征，不能只检查贴纸、标志、水印和重复角色等通用词。

当前 Z-Image 提示词预算固定如下：

| 内容 | 正向提示词预算 |
| --- | ---: |
| 本帧主要内容和必需主体 | 四百个字符 |
| 规范身份文字 | 四百个字符 |
| 安置和场景融合 | 三百个字符 |
| 画面风格 | 一百个字符 |

正向提示词总长度不得超过一千二百个字符，负向提示词不得超过八百个字符。规范身份、必需主体、安置和融合都属于受保护事实；任何受保护部分超过自己的预算时，必须在调用图片模型前返回明确错误，禁止静默截断。负向提示词完成确定性去重后仍超过八百字符时同样失败，不能截掉角色禁止特征或主体保护。补充身份细节和装饰性风格只能使用剩余预算。

各段预算包含段间分隔符和编译器加入的固定句式，四段编译后的总长度必须再次执行一千二百字符总门禁。现有两万字符基础正向提示词预算和一万二千字符基础负向提示词预算只是投影输入安全上限，不是模型最终输入上限。

普通编译路径、已含角色身份的输入路径和旧请求兼容路径必须汇入同一个最终编译器；最终编译结果必须再通过 Z-Image 专用提示词对象和适配器门禁。任何路径都不得直接把通用 `FinalVisualPromptBundle` 当成已经满足 Z-Image 长度限制的最终请求。

### 6.5 模型适配

1. 最终视觉合同保持模型无关，不能把 Z-Image 专用文字写入事实模型。
2. 当前 Z-Image 适配器只消费正向提示词和负向提示词。
3. 当前工作流没有声明方框、遮罩、深度或姿态能力时，系统不得发送或假装使用这些能力。
4. 未来接入 OpenAI 图片模型时，继续消费同一份身份、安置和融合合同，再由新的模型适配器转换请求。
5. 未来模型拥有更强区域控制能力时，属于单独需求，不反向污染当前文字合同。
6. 当前 `max_area_ratio` 只用于内部安全上限和旧请求兼容；Z-Image 适配器只发送由该上限约束后的相对大小文字，不发送面积百分比。
7. 当目标图片工作流为 Z-Image 时，标准视频生成主链必须显式调用 Z-Image 适配器，并把适配器验证后的正向和负向提示词原样传给图片工作流；集成测试必须检查实际媒体请求，而不只检查编译器返回值。
8. 适配器必须拒绝超长提示词以及当前工作流未声明的区域控制参数，不能依赖下游节点自行忽略。

### 6.6 保存与追踪

每帧必须保存：

- 角色档案标识和身份内容散列。
- 本帧安置计划。
- 本帧场景融合计划。
- 最终正向提示词。
- 最终负向提示词。
- 合同版本和内容散列。

现有 `PromptPlan` 只保存最终正向提示词，本次必须新增可选的 `final_negative_prompt`、`identity_content_sha256`、`contract_content_sha256` 和 `contract_version` 兼容字段；旧记录允许为空，新生成的第4.5版系列视觉签名记录必须全部非空。完整的每帧身份、安置和融合合同继续保存在提示词追踪工件中，`PromptPlan` 保存能够定位并验证该合同的版本和散列。`prompt_sections` 必须由投影后的第4.5版最终合同生成，至少区分主要内容、固定身份、角色作用、安置、场景融合、风格和主体保护，不能继续沿用投影前合同。实际发送请求必须与 `PromptPlan` 和追踪工件中的最终正负向提示词逐字一致。保存这些信息只用于复现和排查提示词，不保存自动成图检测结果。

`contract_content_sha256` 对合同版本、帧标识、必需主体、身份内容散列、角色作用、安置计划和场景融合计划的规范化固定键序 JSON 计算；排除合同内容散列字段本身、时间戳、追踪标识、审计状态和最终提示词，避免循环计算和非语义字段导致散列漂移。规范化规则与身份内容散列一致。

### 6.7 用户流程

本需求不增加新的用户操作。

- 用户仍按现有方式一次性运行完整视频生成流程。
- 系统在生成每张分镜图前自动完成角色安置和场景融合规划。
- 用户仍在流程完成后查看最终结果。
- 本文不定义用户查看结果后的处理动作。

## 7. 六帧斑点狗案例

六帧使用同一份斑点狗固定身份文字。每帧只改变动作、位置和场景关系。

1. 第一帧：斑点狗必须落在已有地面或道路上，与场景透视和光线一致。
2. 第二帧：只出现一只斑点狗，不能因提示词重复投影而生成两只。
3. 第三帧：斑点狗与人物和已有地面形成明确关系，不能像后贴吉祥物。
4. 第四帧：斑点狗服从本帧的次要角色作用，不能放大后抢占主体。
5. 第五帧：斑点狗不能替代或遮挡特斯拉、电动汽车或行业变革等上游必需主体。
6. 第六帧：斑点狗可以与人物自然同行，动作、朝向、脚下接触和投影必须与人物所在空间一致。

## 9. 验收标准

### 9.1 自动化合同验收

1. 启用系列视觉签名时，每帧身份、安置和融合合同覆盖率为百分之百。
2. 同一身份输入在所有分镜生成同一个身份内容散列和逐字相同的规范身份文字；任一身份事实变化时散列随之变化。
3. 现有资产档案同时包含 `identity_lock`、`minimal_traits` 和 `identity_anchors` 时，核心特征包含前两组全部非重复值，补充特征包含第三组剩余值，不丢失任何非空身份事实。
4. 每帧最终正向提示词包含位置、前后景、大小、关联对象、支撑关系、动作和与视角相容的可见核心特征。
5. 每帧最终正向提示词包含适用的遮挡、透视、光线、阴影和风格关系。
6. 已含身份特征的基础提示词路径同样包含完整安置和融合条款。
7. 必需主体在最终合同和最终提示词中的保留率为百分之百。
8. 不支持区域控制的工作流不会收到方框、遮罩、深度图或姿态图参数。
9. 生成链中不会调用图片分析、自动验收或自动重试服务。
10. 自动角色解析不会产生障碍物、容器和背景标记类型；显式请求这些类型会在生成前失败。
11. 真实场景和抽象图分别使用各自的保守回退；抽象图合同把物理字段标记为不适用，最终正向提示词不会出现虚构地面、物理接触阴影或“不适用”字样。
12. 普通编译、已含身份输入和旧请求兼容三条路径的最终正向提示词都不超过一千二百个字符，最终负向提示词都不超过八百个字符；受保护事实不会被截断。
13. 三条路径的最终负向提示词都包含全部通用保护词和角色档案中的每一条禁止特征，缺失任一条时门禁失败。
14. 旧面积上限能够稳定映射为相对大小，Z-Image 最终提示词不出现面积百分比。
15. 缺少任一必填安置或融合字段时，最终门禁按帧标识和字段路径失败，审计结果不能记录为通过。
16. 新生成的第4.5版提示词计划保存最终正向提示词、最终负向提示词、身份内容散列、合同内容散列和合同版本，旧记录继续可读。
17. 新生成记录的 `prompt_sections` 来自投影后的第4.5版最终合同，能够逐段对应 `final_prompt` 中的主要内容、固定身份、角色作用、安置、场景融合、风格和主体保护。
18. 标准视频生成集成测试捕获的实际 Z-Image 请求与提示词计划及追踪工件逐字一致，并且不包含未声明的方框、遮罩、深度或姿态参数。
19. 任一帧合同、编译或适配失败时，整批投影失败，不发布部分成功结果。

### 9.2 固定样本人工验收

人工验收只用于开发和发布验证，不进入用户运行流程。

1. 使用固定角色文字、固定六帧脚本、固定模型文件散列、固定工作流文件散列、固定采样参数、固定尺寸和至少三个固定随机种子，对比改造前后不少于十八帧结果；种子列表随验收记录保存。
2. 按统一二值清单逐帧检查角色身份、位置大小、主体关系、落地接触、遮挡、透视、光线和画风；每项只记录通过或失败，不能使用“基本通过”。
3. 全部最终提示词必须通过合同检查，实际媒体请求必须通过适配器预算和能力检查。
4. 必需主体被替代、被严重遮挡或被挤出主要构图属于阻断错误，验收样本中必须为零。
5. “同一角色且属于当前场景”的逐帧联合通过率必须达到百分之八十且不低于改造前基线；改造前基线低于百分之八十时，还必须至少提高二十个百分点。重复角色、贴纸化、悬空和独立展示台分别记录错误率。
6. 每个随机种子的六帧合成视频都必须单独验收，不能用其他种子的成功画面替换失败画面。

## 11. 泼冷水结论

1. 纯文字文生图只能提高位置和融合的稳定性，不能提供像素级硬约束；文档不能把文字合同包装成方框或遮罩能力。
2. “保持角色一致”不能只重复角色名字，必须逐帧复用完整固定身份特征。
3. “自然融入”不是可执行要求，必须拆成支撑关系、遮挡、透视、光线、阴影和画风。
4. 百分比面积对当前文字模型属于虚假精度，应改用相对大小和明确构图关系。
5. 负向提示词只能减少错误，不能替代正向提示词中的具体位置和物理关系。
6. 未来图片模型支持更强区域能力时，可以提升控制精度，但当前合同必须先把角色和场景关系表达完整。
7. 身份内容散列和合同内容散列只能证明输入事实相同、记录可以复现，不能证明图片中的角色视觉一致。
8. 用户运行流程不做成图检测，因此自动化门禁只能证明“发送给模型的合同完整”，最终画面质量必须依靠开发和发布阶段的固定多种子样本验收。

## 12. 完成定义

- 第4.5版投影仍是系列角色身份、安置和融合的唯一入口。
- 每张启用帧都有固定身份、身份内容散列、每帧安置和场景融合合同。
- 文字角色只使用保持角色形态的允许角色类型；规范身份文字逐帧保留全部核心识别特征，本帧可见核心特征与朝向、遮挡和景别相容。
- 最终提示词完整回答“它是谁、在哪里、占多大、与谁发生关系、如何站住、如何受光”。
- 已含角色身份的提示词不能绕过安置和融合编译。
- 当前 Z-Image 工作流只接收真实支持的文字能力。
- 普通编译、已含身份输入和旧请求兼容路径全部进入同一个最终编译器；目标工作流为 Z-Image 时再统一进入 Z-Image 适配器。
- 当前 Z-Image 最终正向和负向提示词满足确定预算，实际发送内容与提示词计划及追踪工件逐字一致并可以完整复现。
- 用户运行流程中没有新增自动检测、自动验收或自动重试。
- 六帧斑点狗多随机种子样本达到人工验收阈值，相关自动化测试全部通过。
- 文档、合同、编译器、提示词追踪和测试使用同一组事实字段。
