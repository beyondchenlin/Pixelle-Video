## 1. 一句话结论

当前代码已经能保证“同一身份被写进每帧提示词”，本次只补齐三件事：明确它在每帧怎么出现、检查真实图片是否正确、失败时只重生当前帧。

## 2. 当前代码事实

| 已有能力 | 当前实现 | 结论 |
| --- | --- | --- |
| 唯一身份入口 | `VisualPromptComposer` 最终调用 `SeriesVisualSignatureProjectionService` | 保留，不建立第二条链路 |

| 最终提示词 | 已有统一编译器和文本门禁 | 改为消费安置合同，删除泛化“绑定某物”表达 |
| 图片分析 | `ImageAnalysisService` 只返回自由文本描述 | 不能直接作为成图门禁 |
| 单帧重生 | 故事板工作台已有单帧重生任务、候选版本和选择能力 | 直接复用为质量重试基础设施 |
| 工件状态 | 图片版本已支持候选、选中、拒绝和失败状态 | 不新增另一套重试数据库 |

当前主链如下：

```text
故事板与帧上下文
  -> VisualPromptComposer
  -> 第4.5版系列视觉签名投影
  -> FinalVisualPromptCompiler
  -> FrameProcessor
  -> 图片工件与故事板工作台
```

当前真正缺失的是：投影服务只有“身份和角色”，没有“数量、位置、关系、支撑面和目标面积”；图片生成后也没有结构化验收。

## 3. 产品目标

### 3.1 阻断级目标

1. 每个启用系列视觉签名的帧，在生图前都有一份结构化安置合同。
2. 上游已经存在的必需主体不能在最终合同中丢失。
3. 真实图片出现数量错误、关键身份错误、主体丢失或严重遮挡时，当前帧不能进入成功状态。
4. 当前帧最多重试两次，不重跑整条视频，不改动已经通过或锁定的帧。
5. 第4.5版投影继续是唯一身份和安置所有者。

### 3.2 质量目标

1. 系列视觉实体使用已有场景关系和已有支撑面，不为自己凭空生成展示台、牌子、盒子或舞台。
2. 角色只决定面积预算范围，不再直接决定最终面积。
3. 身份强度和姿态自由度分开控制，保持同一身份但不锁死姿势。
4. 每次失败都有失败码、证据和实际采用的重试补丁。

### 3.3 非目标

- 不训练新的基础图片模型。
- 不恢复旧场景规划器或旧视觉锚点规划器。
- 不创建斑点狗专用字段、服务或判断分支。
- 不在首期增加遮罩、深度、姿态等当前工作流未声明的控制能力。
- 不把轻微风格差异和主观自然度直接设为自动重试条件。
- 不重写故事板工作台、工件仓库、任务管理器和媒体服务。

## 4. 目标流程

```text
帧上下文、文章具象化、基础视觉简报
  -> 必需主体引用
  -> 第4.5版身份合同
  -> 帧级安置计划
  -> 最终视觉合同
  -> 提示词编译与生成前门禁
  -> 现有媒体服务生成当前帧
  -> 成图证据提取与验收
      -> 通过：选中当前图片版本
      -> 失败：保存拒绝版本并定向重试当前帧
      -> 无法判定：保留候选，只重跑分析或进入人工验收
      -> 两次重试仍失败：当前帧失败
```

## 5. 功能需求

### 5.1 必需主体引用

新增 `RequiredSubjectRef`，同时保留现有字符串主体列表作为兼容输出。主体身份与主体来源分开建模，避免同一主体从多个入口出现时产生多个身份。

最少字段：

| 字段 | 规则 |
| --- | --- |
| `subject_id` | 由帧标识和归一化名称确定性生成，不包含来源和来源顺序 |
| `name` | 当前编译器继续使用的主体名称 |
| `normalized_name` | 用于去重和稳定生成主体标识，不进入用户可见提示词 |
| `source_refs` | 非空来源列表，每项包含 `source_kind` 和 `source_index` |
| `required` | 当前版本固定为真 |

规则：

1. 按当前 `_required_subjects` 的并集语义收集，不允许后来源覆盖先来源。
2. 同名主体归一化后只生成一个主体引用，所有来源追加到 `source_refs`；来源计数等于该列表长度。
3. 上游主体数量大于零、最终主体引用数量等于零时，在调用媒体服务前失败。
4. 没有上游主体的抽象画面继续合法，不强行制造主体。
5. 来源列表按来源类型和来源序号稳定排序；新增相同来源不能改变已有主体标识。
6. 来源引用只保存类型和序号，不保存额外私有原文。
7. `source_kind` 只允许文章具象化、基础视觉简报、主主体、次主体和显式必需主体五类；`source_index` 是对应来源集合内从零开始的稳定序号。

### 5.2 帧级安置计划

新增 `VisualEntityPlacement`，由第4.5版投影服务持有。最少字段如下：

| 字段 | 规则 |
| --- | --- |
| `schema_version` | 首版固定为一 |
| `frame_id` | 必须与最终视觉合同一致 |
| `profile_id` | 必须与当前身份快照一致 |
| `expected_count` | 默认一，必须大于零 |
| `presence_mode` | 完整、边缘、背景或局部 |
| `required_visible_traits` | 本帧必须能看见的身份特征，是身份快照特征的非空子集 |
| `bind_target_ref` | 引用已知主体、已有道具或已有场景区域 |
| `support_surface` | 已有道路、地面、桌面或场景结构；不能是新造承载物 |
| `action` | 站立、坐、趴、行走、观察、经过或静止 |
| `spatial_relation` | 旁边、后方、前方、路边、门口或背景 |
| `placement_region` | 左、中、右与前、中、后景的宽松组合 |
| `target_area_ratio` | 本帧目标面积 |
| `max_area_ratio` | 本帧硬上限，不能小于目标面积 |
| `allow_new_support_prop` | 默认假 |
| `identity_strength` | 身份保持强度 |
| `pose_freedom` | 姿态自由度 |
| `planner_confidence` | 零到一 |
| `decision_codes` | 只保存固定决策码，不保存完整推理文本 |

面积预算：

| 场景角色 | 目标面积 | 本帧硬上限 |
| --- | ---: | ---: |
| 背景识别 | 2%—4% | 5% |
| 安静旁观 | 3%—6% | 8% |
| 引导或操作 | 5%—9% | 12% |
| 核心参与 | 8%—12% | 20% |

最终硬上限取“用户请求上限、现有角色上限、本帧安置上限”三者中的最小值。现有安静旁观角色直接使用百分之十六上限的行为必须停止。

身份验收规则：

1. 完整出现时，`required_visible_traits` 必须包含身份快照中的全部必需特征。
2. 边缘、背景或局部出现时，只验收 `required_visible_traits`，但至少保留一个足以识别身份的核心特征。
3. 安置区域无法展示任何核心身份特征时，该候选必须在生成前被淘汰，不能依赖成图门禁补救。
4. 成图失败码 `MISSING_IDENTITY_TRAIT` 只针对本帧 `required_visible_traits` 判断，不能要求局部画面展示合同未要求可见的身体特征。

### 5.3 安置规划规则

1. 规划输入只使用当前已经存在的 `BaseVisualBrief`、帧上下文、文章具象化计划、身份快照和系列角色。
2. 优先读取基础视觉简报中的主主体、主体关系、场景、空间布局、道具、可安置位置和禁止区域。
3. 候选只允许引用输入中已存在的主体、道具、表面和场景区域。
4. 先用确定性规则生成候选，再按主体安全、自然关系、空间适配、身份可辨识度和构图干扰排序。
5. 没有安全候选时直接返回安置失败，不能让提示词编译器临时补关系。
6. 旧规划器中的通用词表和规则只能提取到新的中立模块，禁止从新主链直接调用旧规划器。

### 5.4 最终合同与提示词

1. `FinalVisualPromptContractV45` 增加主体引用和安置计划。
2. `FinalVisualPromptCompiler` 必须把明确的目标、动作、位置、支撑面和面积编译进正向提示词。
3. 当前“绑定某个真实道具、表面或辅助动作”的泛化句子必须删除，因为它把决定重新交给图片模型。
4. 当前“基础提示词已经包含全部身份特征就直接保留”的快捷路径，也必须补入同一份安置条款，不能绕过安置合同。
5. 生成前门禁检查主体、身份、数量、关系字段、面积上下限和禁止新增承载物。
6. 工作流只声明文本能力时，系统只发送正向和负向提示词；声明参考图能力时，复用现有参考图绑定机制。禁止伪造工作流能力。

### 5.5 成图验收

新增结构化成图门禁。首期复用现有多模态调用和图像输入安全能力，不改造通用自由文本图片分析服务。

门禁状态固定为通过、失败和无法判定三类。只有业务画面检查明确失败时才允许重生图片；分析服务本身失败不能消耗图片重生次数。

阻断级检查：

| 失败码 | 条件 |
| --- | --- |
| `DUPLICATE_ENTITY` | 实际数量大于期望数量 |
| `MISSING_ENTITY` | 视觉实体未出现 |
| `MISSING_IDENTITY_TRAIT` | 本帧 `required_visible_traits` 中的关键身份特征缺失 |
| `REQUIRED_SUBJECT_MISSING` | 必需主体未出现 |
| `SUBJECT_OCCLUSION` | 视觉实体严重遮挡必需主体 |
| `AREA_OVERFLOW` | 实体面积超过本帧硬上限 |
| `INVENTED_SUPPORT_PROP` | 出现仅用于承载视觉实体的新台子、牌子、盒子或舞台 |

软警告只记录，不自动重试：轻微位置漂移、关系自然度偏低和轻微风格差异。

分析异常码：

| 异常码 | 处理 |
| --- | --- |
| `ANALYZER_TIMEOUT` | 图片版本保持候选，不重生图片；当前验收任务失败并允许单独重跑分析 |
| `ANALYZER_UNAVAILABLE` | 图片版本保持候选，不重生图片；记录服务不可用并进入人工验收 |
| `ANALYZER_INVALID_RESULT` | 结构化结果修复一次；仍无效时保持候选并进入人工验收 |

门禁结果必须包含状态、失败码或异常码、逐项置信度、证据摘要、分析器版本、合同摘要、面积测量方法和重试建议。日志和审计不得保存图片数据、完整主体文本、完整身份特征或带凭证的地址。

人工验收只能在故事板工作台中对候选版本显式执行，必须记录验收人、验收时间、逐项检查结论和覆盖原因；人工通过可以选中候选，但不能修改原始分析结果或伪装成自动门禁通过。

面积判定规则：

1. 面积比例等于视觉实体可见分割区域像素数除以整帧像素数。
2. 只有分析器返回有效分割区域且置信度不低于百分之九十时，`AREA_OVERFLOW` 才能成为阻断项。
3. 实测面积必须超过硬上限至少一个百分点才判定超限，避免分割边缘抖动触发误杀。
4. 没有分割区域、置信度不足或只返回自由文本时，面积结果为无法判定，只记录警告，不重生图片。
5. 面积阻断上线前，必须在人工作为真值的评测集上单独完成校准；现有多模态自由判断不能直接承担百分比阻断。

### 5.6 单帧重试

1. 总生成上限为首次生成加两次重试。
2. 每次失败图片保存为当前帧工件的拒绝版本，不覆盖已选中版本。
3. 第一次重试按失败码修改数量、身份强度、面积、位置或主体保护。
4. 第二次重试进入保守模式：缩小面积、减少互动、移到边缘或背景。
5. 第三次验收仍失败时，当前帧和对应工件标记失败。
6. 锁定图片禁止自动替换；已经通过的其他帧禁止重新生成。
7. 手动单帧重生继续生成候选版本，成图门禁结果随候选版本保存。
8. 每次生成使用由帧标识、执行合同标识和尝试序号组成的幂等键；相同幂等键只能对应一个任务和一个图片版本。
9. 自动重试与手动重生复用现有任务管理器的幂等任务登记和生成租约；同一帧同一时间只能有一个生成任务持有有效租约。
10. 入队前和自动选中前各检查一次锁定状态、执行合同散列和最新尝试标识。过期任务的图片可以保存为候选，但不能自动选中，也不能触发下一次重试。
11. 分析异常只允许重跑分析任务，不增加生成尝试序号，也不消耗两次图片重试额度。

### 5.7 持久化与审计

执行合同与观测摘要必须分开，并确定唯一事实源：

1. 新增不可变的 `VisualEntityExecutionContractArtifact` 作为唯一执行事实源，复用现有项目工件仓库和版本生命周期，不新增数据库。
2. 执行工件完整保存主体引用、帧级安置计划、第4.5版最终合同、最终正向提示词、最终负向提示词、合同版本和内容散列。
3. `PromptPlan` 保留现有 `final_prompt` 作为只读兼容快照，同时新增执行工件标识和内容散列；兼容快照必须与执行工件中的正向提示词完全一致，不一致时拒绝生成。
4. 每次成图分析生成独立门禁结果工件，由图片版本保存门禁结果工件标识；提示词计划不保存“最新门禁结果”这类可变指针。
5. 规划快照和生成事件只保存合同标识、版本、计数、失败码、面积值和摘要散列。
6. 每次生成使用新的尝试标识，但保持同一帧标识、提示词计划标识和图片工件标识。
7. 成功图片必须能追溯到提示词计划、执行工件、门禁结果和生成尝试。

## 7. 实施顺序

### 阶段零：验收资产准备

- 在 `tests/fixtures/series_visual_signature_entity_control/` 新增六帧合同输入、期望安置结果和固定失败码。
- 六帧真实图片必须使用已获许可、已脱敏的固定文件，保存到同目录的 `images/` 子目录，并记录文件散列、尺寸、人工标签和预期结果。
- 二百帧评测集不提交仓库；保存到项目受控工件存储，仓库只保留不含凭证的匿名清单、内容散列和标签版本。
- 合同夹具与真实图片评测分开：前者进入持续集成，后者进入发布前评测。

完成条件：六帧不再只是文档描述，输入、图片、人工标签和预期结果都能按固定标识复现。

### 阶段一：合同与静态门禁

- 加入主体引用、安置计划、面积预算和生成前门禁。
- 把六帧问题固化为合同级测试夹具。
- 暂不调用真实图片分析。

完成条件：每帧合同可序列化；缺主体、非法引用、新承载物和面积冲突全部在生图前失败。

### 阶段二：正式链路接入

- 在第4.5版投影服务内生成安置计划。
- 编译器消费安置计划。
- 提示词计划保存执行合同引用。

完成条件：旧规划器调用次数为零；身份已在基础提示词中时也不能绕过安置条款。

### 阶段三：成图门禁观察期

- 新增结构化成图分析。
- 只记录结果，不阻断交付，不自动重试。
- 对六帧样本和二百帧人工标注样本计算漏检与误杀。
- 面积检查只在有效分割区域上评估；自由文本面积判断只记录观察结果。

完成条件：各阻断类别达到第8.2节的召回率要求；正常样本误杀率不高于百分之五；面积分析完成独立校准。

### 阶段四：强制门禁与单帧重试

- 启用阻断级检查。
- 接入工件版本状态和单帧重试。
- 删除临时兼容和重复决策入口。
- 只有完成分割校准后才启用面积阻断；未完成时面积继续作为软警告。

完成条件：任一单帧失败不触发其他帧重新生成，失败图片不进入选中状态。

## 8. 验收标准

### 8.1 六帧黄金样本

六帧验收必须绑定阶段零产出的固定样本清单，不能用临时图片或仅凭文字描述代替。每个样本必须有图片散列、人工标注版本、预期失败码或通过结论。

1. 第一帧必须有明确支撑面和场景关系。
2. 第二帧出现两只狗时返回重复实体失败码。
3. 第三帧必须与人物和现有地面形成关系，不能像后贴吉祥物。
4. 第四帧不得超过本帧面积上限。
5. 第五帧必须保留特斯拉、电动汽车或行业变革中的上游必需主体。
6. 第六帧人物与狗自然同行时通过，证明系统不是一味隐藏视觉实体。

### 8.2 二百帧评测集

统计口径固定如下：

- “合同帧”指进入生成前门禁的二百个源帧，每个源帧只计一次。
- “生成尝试”指首次生成和后续重试产生的每个图片版本。
- “最终选中图片”指通过强制门禁后被选中的每帧唯一图片。
- 成图缺陷以双人人工复核标签为真值；意见不一致时由第三人裁决。
- 每个阻断类别至少包含二十个已标注负样本，同一图片可以属于多个类别。

| 指标 | 统计对象与公式 | 发布门槛 |
| --- | --- | ---: |
| 必需主体合同保留率 | 最终合同含全部上游主体的合同帧数除以有上游主体的合同帧数 | 100% |
| 阻断缺陷召回率 | 被门禁正确阻断的缺陷样本数除以人工标注缺陷样本数，逐失败码计算 | 每类不低于95% |
| 正常样本误杀率 | 被错误阻断的正常样本数除以人工标注正常样本数 | 不高于5% |
| 最终严重缺陷逃逸数 | 最终选中图片中主体丢失、严重遮挡、重复实体、实体缺失、关键特征缺失或新承载物的图片数 | 0 |
| 最终面积超限逃逸数 | 启用分割面积阻断后，最终选中图片中人工确认超限的图片数 | 0 |
| 三次内成功率 | 三次生成内得到合格图片的合同帧数除以全部合同帧数 | 不低于95% |
| 单帧重试隔离率 | 未改变其他帧和锁定帧的重试次数除以全部重试次数 | 100% |
| 并发去重率 | 只产生一个有效任务和一个图片版本的并发提交组数除以全部同幂等键并发提交组数 | 100% |

首次生成中的重复、遮挡和面积问题只作为模型质量观察指标，不与最终选中图片的发布指标混算。

三十帧只能作为连续冒烟检查，不能承担百分之二、百分之三这类比例指标的统计验收。

### 8.3 自动化测试

- 模型测试：字段校验、版本、序列化、未知版本拒绝。
- 服务测试：主体合并、候选过滤、面积预算、纯编译和失败码映射。
- 架构测试：第4.5版唯一所有权、旧规划器不可达、成图门禁不反向修改合同。
- 集成测试：生成、验收、拒绝版本、两次重试、分析异常、锁定帧、其他帧不变、重复提交和过期任务回写。
- 真实测试：六帧黄金样本和二百帧评测集。

## 9. 开源复用决策

首期不新增视觉模型依赖，先用现有多模态能力验证合同和非面积门禁闭环。面积只记录软警告；完成分割适配和人工校准后才能成为阻断项。后续分析精度不达标时，只通过分析器适配接口接入以下能力：

| 项目 | 可复用能力 | 许可证判断 | 决策 |
| --- | --- | --- | --- |
| [GroundingDINO](https://github.com/IDEA-Research/GroundingDINO) | 开放词汇目标框、数量和主体定位 | 代码为 Apache-2.0（阿帕奇第2版开源许可证） | 适合作为检测适配器接入 |
| [SAM 2](https://github.com/facebookresearch/sam2) | 实体分割和面积计算 | 模型与主要代码为 Apache-2.0（阿帕奇第2版开源许可证） | 适合作为分割适配器接入 |
| [OpenCLIP](https://github.com/mlfoundations/open_clip) | 参考图与成图相似度 | 代码为 MIT（麻省理工学院宽松许可证），模型权重许可证各不相同 | 只在锁定具体权重许可证后接入 |
| [IP-Adapter](https://github.com/tencent-ailab/IP-Adapter) | 参考图身份控制 | 代码为 Apache-2.0（阿帕奇第2版开源许可证） | 通过现有工作流参考图绑定使用，不直接侵入核心代码 |

引入任何代码或模型权重前，必须分别核对代码许可证、权重许可证、依赖许可证、显存成本和当前工作流兼容性；许可证判断属于工程风险提示，不是正式法律意见。

## 10. 泼冷水结论

1. 数据模型不是最难部分，成图门禁误判才是发布风险，所以必须先观察、后强制。
2. 当前基础视觉简报仍有较多自由文本，首版只能使用受控词表和固定枚举，不能假装已经拥有精确场景图。
3. 当前工作流能力只稳定声明负向提示词和参考图，首期不能承诺遮罩、深度和姿态控制。
4. 当前提示词计划只保存最终正向提示词，单帧重生链还没有完整负向提示词和安置执行合同；不先补齐持久化，重试就无法复现。
5. 六帧案例能证明问题被修复，不能证明系统稳定；发布统计必须使用二百帧人工标注评测集。
6. 自动重试和手动重生共享同一帧资源；不复用现有幂等登记和生成租约，就会产生重复图片和错误回写。

## 11. 完成定义

- 第4.5版仍是唯一身份和安置所有者。
- 每个启用视觉签名的帧都有版本化安置计划。
- 最终提示词不再包含未决策的泛化安置表达。
- 真实成图门禁返回结构化证据和稳定失败码。
- 分析服务异常不会触发图片重生，面积阻断只在分割校准通过后启用。
- 当前帧最多重试两次，其他帧和锁定帧保持不变。
- 相同幂等键只产生一个有效任务，过期任务不能自动选中图片或触发后续重试。
- 六帧黄金样本与二百帧评测指标全部通过。
- 旧规划器未进入新主链，也没有新增斑点狗专用抽象。
- 代码、测试、运行手册和可观测字段保持一致。
