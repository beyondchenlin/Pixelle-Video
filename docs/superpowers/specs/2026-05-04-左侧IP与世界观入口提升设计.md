# 左侧 IP 与世界观入口提升设计

日期：2026-05-04

## 0. 结论

当前 `dev` 已经具备 `generation_world_hint`、世界观草稿接口、`ContentWorldPlanner`、IP 使用规划和最终图片提示词消费链路。新的问题不是后端链路缺失，而是生成页入口位置不合理：

- 当前 IP 选择主入口在中间的风格/图片区域；
- 当前“世界观提示”“根据文案生成”“使用 IP 默认”藏在左侧的高级分镜规划内部；
- 高级分镜默认不启用，用户在输入文案时看不到 IP 与世界观设置；
- 左侧文案区需要读取中间风格区写入的 `style_ip_asset_bibles` / `style_ip_profile_world_hint`，形成渲染顺序耦合。

本轮采用的修正方向是：

**在左侧内容输入区新增一等模块“IP 与世界观设定”，与“分镜规划”同层级；该模块成为标准生成时选择 IP、回填 IP 默认世界观、根据文案生成世界观提示、手动编辑世界观提示的主入口。高级分镜规划只保留镜头、分镜、预设、连续性和逐帧覆盖能力，不再承担 IP/世界观主入口职责。**

## 1. 目标

1. 用户在输入文案时即可看到 IP 与世界观设置，不依赖打开高级分镜。
2. IP 选择和本次世界观提示位于同一个左侧模块，符合“先写文案，再决定这个 IP 如何融入本次内容”的主路径。
3. 左侧模块成为生成请求的单一事实源，正式生成请求只继续发送 `generation_world_hint` 和现有 IP 控制字段。
4. 去掉左侧对中间风格区渲染顺序的依赖，避免 `content_input.py` 读取由 `style_config.py` 稍后写入的状态。
5. 复用当前已落地的后端世界观链路，不重做世界观规划服务，不新增另一套 prompt 生成逻辑。

## 2. 非目标

本轮不做以下内容：

- 不实现 AI Chat 式 IP 创作入口；
- 不实现图片上传反推 IP 提示词；
- 不改 `ContentWorldPlanner` 的主合同；
- 不重写 IP 设计工作台；
- 不把 `generation_world_hint` 写回 AssetBible；
- 不把 IP 长期默认世界观、请求级世界观、IP 身份锚点合并成一个字段；
- 不改变 Z-Image 最终图片生成模型和现有风格提示词前缀机制。

这些能力可以在后续阶段继续做，但不应混入本轮入口位置和数据流修正。

## 3. 当前代码事实

### 3.1 左侧内容输入区

文件：`web/components/content_input.py`

`render_content_input()` 负责左侧主内容输入。单条模式下当前顺序是：

1. 批量模式开关；
2. 生成/固定文案模式；
3. 文案输入；
4. 标题输入；
5. 脚本文案生成参数；
6. 分镜规划参数；
7. 提示词生成性能参数。

`render_storyboard_generation_controls()` 目前还会调用 `render_storyboard_advanced_controls()`，并把高级分镜返回的 `generation_world_hint` 合并进正式请求。

### 3.2 高级分镜规划区

文件：`web/components/storyboard_planning_controls.py`

`render_storyboard_advanced_controls()` 当前承担两类职责：

- 正确职责：世界预设、镜头预设、连续性强度、角色策略、镜头策略、逐帧覆盖；
- 当前不合理职责：请求级 `世界观提示` 输入、`根据文案生成`、`使用 IP 默认`。

后一类职责应从高级分镜中提升到左侧一级模块。原因是它不是高级分镜专属能力，而是每次标准生成都应该能使用的 IP 融入前置设定。

### 3.3 中间风格/图片区

文件：`web/components/style_config.py`

中间区域当前在图片配置附近加载 IP AssetBible，并渲染 `render_ip_prompt_chain_controls()`。它还写入：

- `style_ip_asset_bibles`
- `style_ip_profile_world_hint`

左侧随后尝试读取这些状态，但在 Streamlit 的页面布局里，左侧通常先渲染，中间后渲染。这个依赖方向是错误的。

### 3.4 IP 选择控件

文件：`web/components/ip_prompt_chain_controls.py`

现有 `render_ip_prompt_chain_controls()` 已经具备：

- 启用 IP；
- 选择 AssetBible；
- 选择 IPProfile；
- 返回 `ip_enabled`、`ip_asset_bible_id`、`ip_profile_id`；
- 提供辅助字段 `ip_profile_world_hint`。

这部分逻辑可以复用，但不应继续被定位为“风格区主入口”。更合理的做法是把可复用选择逻辑抽到左侧 IP/世界观模块使用，中间风格区不再是标准生成时选择 IP 的主要路径。

## 4. 推荐产品结构

左侧内容区建议调整为：

1. 文案输入；
2. 标题输入；
3. **IP 与世界观设定**；
4. 脚本文案生成参数；
5. 分镜规划；
6. 提示词生成性能。

其中“IP 与世界观设定”作为左侧一级模块展示，不挂在“启用高级分镜规划”下面。

模块内包含：

- `启用 IP` 开关；
- AssetBible 选择；
- IPProfile 选择；
- 当前 IP 名称/简短摘要；
- `世界观提示` 文本框；
- `根据文案生成` 按钮；
- `使用 IP 默认` 按钮。

推荐默认折叠策略：

- 模块本身默认展开或轻量展开，至少保证用户能看到“启用 IP”和“世界观提示”入口；
- 高级说明可以折叠；
- 高级分镜仍可默认折叠，因为它是专业分镜调参，不是 IP 入口。

## 5. 数据流设计

### 5.1 单一事实源

新增左侧生成页状态前缀：

- `content_ip_enabled`
- `content_ip_asset_bible_id`
- `content_ip_profile_id`
- `content_ip_asset_bibles`
- `content_ip_profile_world_hint`
- `content_generation_world_hint`
- `content_generation_world_hint_source`

正式请求 payload 中继续使用现有合同字段：

- `ip_enabled`
- `ip_asset_bible_id`
- `ip_profile_id`
- `generation_world_hint`

前端内部可以保留 `content_ip_profile_world_hint` 作为按钮回填和草稿接口辅助输入，但它不能进入正式生成请求。

### 5.2 读取 AssetBible 的边界

左侧模块通过现有 `resolve_ip_design_client()` 和 `load_ip_prompt_chain_asset_bibles()` 加载 AssetBible。为了避免函数名继续表达“style”语义，实施时应增加一个生成页语义的 wrapper：

- 推荐新增：`web/components/content_ip_world_controls.py`
- 该文件负责左侧 IP/世界观模块；
- 可以复用 `ip_prompt_chain_controls.py` 中的纯解析 helper；
- 不在 `style_config.py` 中继续写入左侧所需状态。

### 5.3 与中间风格区的关系

中间风格区继续负责：

- 图片工作流选择；
- 图片比例/分辨率；
- 风格提示词前缀；
- 图片提示词前缀库；
- 其他媒体生成参数。

中间风格区不再作为标准生成 IP 选择主入口。

迁移策略建议：

- 第一阶段：左侧模块成为权威入口，中间风格区隐藏或移除原 IP 选择控件；
- 如担心兼容历史会话，可以短期保留读取旧 `style_ip_*` 状态的迁移函数，把旧状态复制到 `content_ip_*`，但 UI 不继续展示两套选择器；
- 不允许左侧和中间同时展示两套可编辑 IP 选择器，否则用户会不知道哪套生效。

### 5.4 与高级分镜的关系

高级分镜继续返回：

- `world_preset_id`
- `shot_preset_id`
- `consistency_strength`
- `content_mode`
- `role_strategy`
- `role_locking_strength`
- `shot_strategy`
- `frame_overrides`

高级分镜不再渲染：

- `storyboard_generation_world_hint` 文本框；
- `storyboard_world_hint_generate_from_content` 按钮；
- `storyboard_world_hint_use_ip_default` 按钮。

左侧 IP/世界观模块返回 `generation_world_hint`，再与分镜 payload 合并。这样世界观提示不依赖高级分镜启用状态。

## 6. 交互行为

### 6.1 手动编辑

用户可直接编辑 `世界观提示`。文本框保存到 `content_generation_world_hint`，返回 payload 时映射为 `generation_world_hint`。

如果用户手动编辑，则 `content_generation_world_hint_source` 标记为 `manual`。该 source 只用于 UI 和调试，不进入正式生成合同。

### 6.2 使用 IP 默认

按钮行为：

1. 读取当前选中 IPProfile 的 `world_hint`；
2. 如果未启用 IP、未选择 IP、或该 IP 没有默认世界观，显示 warning；
3. 如果存在，覆盖当前 `content_generation_world_hint`；
4. 标记 `content_generation_world_hint_source = "ip_default"`；
5. 不调用 API；
6. 不写回 AssetBible。

### 6.3 根据文案生成

按钮行为：

1. 读取当前标题和文案；
2. 读取当前分镜世界预设，如果用户未启用高级分镜或未选择世界预设，则传 `None`；
3. 读取当前选中 IP 的 `IPProfile.world_hint` 作为可选辅助输入；
4. 调用现有 `POST /api/content/world-hint-draft`；
5. 用响应中的 `world_hint_draft` 覆盖 `content_generation_world_hint`；
6. 标记 `content_generation_world_hint_source = "generated_from_script"`；
7. 不触发正式生成；
8. 不把 `generation_world_profile` 暴露成用户必须编辑的 JSON。

### 6.4 未启用 IP 的情况

未启用 IP 时仍允许填写或根据文案生成 `世界观提示`。原因是世界观提示是请求级内容，不只是 IP 的附属字段。

区别是：

- `使用 IP 默认` 不可用或点击后提示；
- `根据文案生成` 不传 `ip_default_world_hint`；
- 正式生成请求中 `ip_enabled=False`，但仍可以有 `generation_world_hint`。

## 7. 合同边界

正式生成请求中只允许以下世界观相关正式字段：

- `generation_world_hint`

允许 IP 相关正式字段：

- `ip_enabled`
- `ip_asset_bible_id`
- `ip_profile_id`

以下字段只能是前端辅助状态或草稿接口参数，不能进入正式生成请求：

- `ip_profile_world_hint`
- `content_ip_profile_world_hint`
- `generation_world_hint_source`
- `world_hint_draft`
- `hint_source`

长期资产级字段仍是：

- `IPProfile.world_hint`

请求级字段不能覆盖它，也不能写回它。

## 8. 测试策略

### 8.1 单元测试

新增左侧模块测试：

- 未启用 IP 时返回 `ip_enabled=False`，不加载 AssetBible；
- 启用 IP 后加载 AssetBible 并返回选中 IP；
- 当前 IP 有 `world_hint` 时，按钮“使用 IP 默认”能回填世界观提示；
- 当前文案存在时，按钮“根据文案生成”调用 `generate_world_hint_draft` 并回填；
- 当前文案为空时，显示 warning，不调用接口；
- 返回 payload 中包含 `generation_world_hint`，但不包含 `ip_profile_world_hint`。

### 8.2 集成/回归测试

需要覆盖：

- `render_content_input()` 左侧返回 payload 能合并 IP 与世界观模块；
- 高级分镜未启用时，`generation_world_hint` 仍然可以出现在返回 payload；
- 高级分镜启用时，世界预设和镜头预设仍按原合同返回；
- 中间 `style_config.py` 不再向正式 payload 注入另一套 IP 选择结果；
- `output_preview.py` 正式请求仍只复制 `generation_world_hint`，不复制辅助字段。

### 8.3 文档/静态检查

用 `rg` 检查：

- `storyboard_world_hint_generate_from_content` 不再出现在高级分镜 UI；
- `storyboard_world_hint_use_ip_default` 不再出现在高级分镜 UI；
- `style_ip_profile_world_hint` 不再被左侧内容输入读取；
- 正式请求 payload 中没有 `ip_profile_world_hint`。

## 9. 风险与取舍

### 9.1 为什么不只把按钮从高级分镜移动出来

只移动按钮会留下 IP 选择仍在中间风格区的问题。左侧仍需要读取中间状态，渲染顺序耦合不会消失。正确修复必须把 IP 选择和世界观提示一起提升为左侧模块。

### 9.2 为什么不保留两套 IP 选择器

两套选择器会制造事实源冲突。用户在左侧选了 A、在中间选了 B，最终到底哪个生效会变得不透明。标准生成只应有一个权威入口。

### 9.3 为什么世界观提示不依赖高级分镜

世界观提示描述的是本次文案发生的世界和 IP 融入方式。它会影响后续分镜规划、IP 使用规划和最终图片提示词，不是高级分镜的局部配置。因此它必须在高级分镜之前或同层级出现。

### 9.4 为什么不把世界观提示自动生成成隐藏字段

用户需要能审核和编辑。世界观提示会影响最终画面内容，不能在用户不可见的地方自动覆盖。

## 10. 验收标准

1. 用户打开生成页左侧，在不启用高级分镜的情况下，也能看到并使用“IP 与世界观设定”。
2. 用户可以在左侧选择已有 IP。
3. 用户可以点击“使用 IP 默认”把当前 IP 的默认世界观回填到本次 `世界观提示`。
4. 用户可以点击“根据文案生成”基于当前文案生成本次世界观提示草稿。
5. 用户可以手动编辑本次世界观提示。
6. 正式生成请求仍只使用 `generation_world_hint` 表示本次世界观。
7. `ip_profile_world_hint` 只作为辅助上下文使用，不进入正式请求。
8. 高级分镜不再是 IP/世界观入口，只保留分镜和镜头规划职责。
9. 左侧内容输入不再依赖 `style_config.py` 写入的 `style_ip_asset_bibles` 或 `style_ip_profile_world_hint`。
10. 相关单元测试、回归测试和静态检查通过。

## 11. 与既有文档的关系

本设计不推翻以下已合并链路：

- `docs/superpowers/specs/2026-05-04-生成页世界观提示设计.md`
- `docs/superpowers/specs/2026-05-04-生成页世界观提示辅助回填设计.md`

它修正的是上述能力在前端生成页的入口位置和模块职责。此前世界观提示被放进高级分镜，是可运行但不符合主路径的实现；本设计将其提升为左侧一级入口，并把高级分镜重新收敛到分镜规划职责。
