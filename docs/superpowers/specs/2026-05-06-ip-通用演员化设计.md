# IP 通用演员化设计

## 1. 结论

当前 IP 系统有两个层级的缺陷：

1. **数据层**：`identity_lock` 把"视觉身份"和"职业职能"焊死在一起（"白色卡通兔子"和"古城文旅向导"同级并列），导致 IP 离开古城场景就无处安放。
2. **消费层**：`IPUsagePlanner` 对所有帧做确定性拼接——把所有 `identity_lock + identity_anchors` 无差别注入每一帧，角色永远是"导游"，占比永远是"中等"，没有帧间变化。

结果是：每张图 IP 占比都很大，姿态都是讲解者，无法融入用户内容的多样性（爱情、科技、美食……）。

本设计的目标是把 IP 从"固定职能的吉祥物"升级为"可适配不同场景的通用演员"。

## 2. 核心设计：三层分离

```
┌──────────────────────────────────────────────────────────────┐
│  Layer 1: 视觉身份 (Visual Identity)                         │
│  "它长什么样" — 不变                                          │
│  白色卡通兔子、蓝色领结、长耳朵、浅粉色耳朵内侧、圆润脸型        │
├──────────────────────────────────────────────────────────────┤
│  Layer 2: 角色职能 (Role & Behavior)                         │
│  "它在这场戏里做什么" — 按视频/场景可变                        │
│  导游讲解 / 情感陪伴 / 路人观察 / 画面主角 / 画外不出镜         │
├──────────────────────────────────────────────────────────────┤
│  Layer 3: 出场规格 (Frame Presence)                          │
│  "它占多大画面、什么距离" — 逐帧可变                           │
│  全身出镜 / 半身出镜 / 局部细节 / 远景融入 / 不出镜            │
└──────────────────────────────────────────────────────────────┘
```

**Layer 1** 由用户在设计工作台定义，是硬约束——无论什么场景都不能丢。

**Layer 2 和 Layer 3** 由 LLM 在生成时根据用户文案内容**自由决定**——系统告诉 LLM"这个 IP 长什么样、能做什么角色、有什么可变项"，LLM 为每一帧输出自然语言描述 IP 在画面中的样子。

## 3. 与当前架构的关系

### 3.1 当前问题

```
用户填写（identity_lock）：
  白色卡通兔子, 古城文旅向导, 亲和好奇的表情, 温和陪伴式讲解者
                              ↑                 ↑
                         职能（可变）        行为模式（可变）

IPUsagePlanner 消费：
  _visible_anchors() → [*identity_lock, *identity_anchors]
  → "白色卡通兔子, 古城文旅向导, 亲和好奇的表情, 温和陪伴式讲解者, 蓝色领结, ..."
  → 所有帧、所有场景、所有内容主题，都一样
```

### 3.2 目标行为

```
Layer 1 视觉身份（用户定义，不变）：
  identity_core: ["白色卡通兔子", "长耳朵", "圆润脸型", "清爽亲和的卡通造型"]
  identity_anchors: ["蓝色领结", "浅粉色耳朵内侧"]

Layer 2 角色（LLM 按帧决定）：
  爱情主题第3帧 → role: "companion", 描述: "兔子坐在咖啡馆角落，温和注视情侣，半身出镜"
  文旅主题第1帧 → role: "guide", 描述: "兔子站在城门前，手持导览旗，全身出镜"
  科技主题第5帧 → role: "observer", 描述: "兔子在实验室背景中，看着屏幕，远景融入"

Layer 3 出场规格（LLM 按帧决定）：
  第1帧 → "全身出镜，占据画面中景，清晰可辨"
  第3帧 → "只露出耳朵和领结一角，作为画面边缘的陪伴暗示"
  第8帧 → "不出镜"
```

### 3.3 数据模型现状

值得注意：`IPFrameAdaptationPackage`（`pixelle_video/models/ip_prompt_planning.py`）已经预留了丰富的帧级字段：

- `outfit_theme` / `outfit_condition` — 服装主题
- `accessories` — 配饰/道具
- `pose` — 姿势
- `continuity_from_previous` — 与上一帧的连续性
- `interaction_target` — 互动对象

它们只是没有被 `IPUsagePlanner` 填充。

本设计不新增 IPFrameAdaptationPackage 字段，只让现有字段真正工作。

## 4. 设计目标

1. `identity_lock` 只包含纯视觉身份，不包含职能、行为、表情。
2. IPProfile 新增 `role_presets` 和 `presence_spectrum`，定义可变的角色和出场范围。
3. `variable_slots` 改为通用适应性描述（服装、道具、动作、表情、互动），不再绑定特定场景。
4. `semantic_boundary` 和 `negative_constraints` 改为通用约束，去掉古城特供内容。
5. IP 生成链路中，LLM 在视觉身份约束下自由决定每帧的角色、出场规格、服装、动作、表情和互动。

## 5. 非目标

本设计不包含：

1. 多 IP Profile 的联合调度。
2. 跨帧连续性的完整实现（`continuity_from_previous` 字段预留但本轮不强制）。  
3. 参考图、LoRA、IPAdapter、图生图。
4. 生成页世界观提示（那是另一个独立设计）。
5. 旧 IPProfile 数据的自动迁移。

## 6. 数据模型变更

### 6.1 IPProfile 新增字段

```python
@dataclass(frozen=True)
class IPProfile:
    # --- 现有字段保持不变 ---
    ip_profile_id: str
    workspace_id: str
    project_id: str
    name: str
    logline: str | None = None
    world_hint: str | None = None
    style_hint: str | None = None
    forbidden_elements: tuple[str, ...] = ()
    
    # --- 重新定义语义的字段 ---
    # identity_lock: 纯视觉身份，去掉职能和行为
    identity_lock: tuple[str, ...] = ()
    # identity_anchors: 视觉辅助锚点，不变
    identity_anchors: tuple[str, ...] = ()
    # identity_suppression_rules: 不变，但内容需要通用化
    identity_suppression_rules: tuple[str, ...] = ()
    
    # --- 重定义语义 ---
    # variable_slots: 改为通用可变项描述，LLM 据此自由创作
    variable_slots: tuple[str, ...] = ()
    
    # --- 通用化 ---
    semantic_boundary: tuple[str, ...] = ()
    negative_constraints: tuple[str, ...] = ()
    
    # --- 新增字段 ---
    # role_presets: IP 可扮演的角色预设
    role_presets: tuple[str, ...] = ()
    # presence_spectrum: 出场规格范围
    presence_spectrum: tuple[str, ...] = ()
    # universal_constraints: 通用硬约束（合并 semantic_boundary + negative_constraints 中的通用部分）
    universal_constraints: tuple[str, ...] = ()
    
    # --- 原有字段不变 ---
    color_palette: Mapping[str, Any] = field(default_factory=dict)
    image_text_palette: Mapping[str, Any] = field(default_factory=dict)
    visible_text_whitelist: tuple[str, ...] = ()
    metadata: Mapping[str, Any] = field(default_factory=dict)
```

### 6.2 字段重新定义

**`identity_lock`（重新定义语义）**

只包含纯视觉身份，不得包含职能、行为、表情、场景。

旧（有问题）：
```
白色卡通兔子, 古城文旅向导, 亲和好奇的表情, 温和陪伴式讲解者
```

新（正确）：
```
白色卡通兔子, 长耳朵, 圆润脸型, 清爽亲和的卡通造型, 蓝色领结, 浅粉色耳朵内侧
```

注意：原 `identity_anchors` 中的视觉锚点（蓝色领结、浅粉色耳朵内侧）合并进 `identity_lock`，因为它们同样是"必须透传的视觉特征"。

**`role_presets`（新增）**

定义 IP 在不同文案场景下可扮演的角色。每条是一个自然语言的角色描述，LLM 据此选择并发挥。

示例（通用化后）：
```
导游讲解者：作为温和的讲解者，面向场景做介绍手势，与场景内容互动
情感陪伴者：作为情感陪伴角色，与画面主体自然互动，温和注视
路人观察者：在画面边缘或背景中静静观察，不抢眼
画面主角：占据画面主体位置，面向镜头
画外不出镜：不出现在画面中，仅作为叙述者声音存在
```

**`presence_spectrum`（新增）**

定义 IP 在画面中的出场规格范围。LLM 据此决定每帧的构图。

示例：
```
全身出镜：完整呈现角色形象，占据画面中景
半身出镜：展示上半身和表情
局部细节：只露出特征性局部，如耳朵、领结一角、背影
远景融入：作为场景中的小元素融入背景
完全不出镜：该帧不出现 IP
```

**`variable_slots`（重新定义）**

旧（古城特供）：
```
表情, 动作, 站位, 手持地图, 手持导览旗, 讲解姿势, 与游客或古城场景的距离, 出场强度
```

新（通用）：
```
服装配饰：可根据场景穿不同的服装，保持角色可识别
手持道具：可根据场景持有不同道具
动作姿势：可根据场景做不同动作
表情神态：可根据场景产生不同表情
互动对象：可与场景中的人或物互动
出场程度：从全身到局部到不出镜
```

**`universal_constraints`（新增，合并 semantic_boundary + negative_constraints 通用部分）**

```
不能变成人类
不能变成其他动物
不能丢失长耳朵和蓝色领结
不能变成写实或恐怖风格
不能变成真人玩偶
不能替代画面中的真实主体（人物、建筑、文物等）
不要变成蓝色兔子（保持白色）
不要出现错误文字和乱码
```

**`semantic_boundary` 和 `negative_constraints` 的定位调整**

保留这两个字段但重新定义：
- `semantic_boundary`：叙事身份边界（它是 XX，不是 XX）
- `negative_constraints`：画面负向约束

两者内容通用化，去掉古城特供内容。如果通用化后内容与 `universal_constraints` 完全重叠，则可废弃这两个字段。

**`identity_anchors` 的定位调整**

视觉锚点合并入 `identity_lock` 后，`identity_anchors` 可保留为"辅助锚点"——在 IP 低出场（LOW_INTRUSION / SYMBOLIC_ONLY）时仍然可见的最小特征集合。如果 `identity_lock` 和 `identity_anchors` 没有区分必要，可以废弃 `identity_anchors`。

本轮不做废弃，但调整内容为：
```
蓝色领结一角, 长耳朵轮廓
```
——即"即使只露出一点也能认出是这个 IP"的最小特征。

当前模型已经完备，包含：

## 7. IPUsagePlanner 改造

### 7.1 当前行为

```python
# 确定性拼接 identity_lock + identity_anchors，所有帧一样
def _visible_anchors(presence_type, ip_profile):
    return tuple([*ip_profile.identity_lock, *ip_profile.identity_anchors])
```

### 7.2 目标行为

IPUsagePlanner 调用 LLM，传入：

1. IPProfile 的 Layer 1-3 信息（visual_identity, role_presets, presence_spectrum）
2. 当前帧的上下文（旁白文本、视觉目标、镜头类型、画面主体）
3. 上一帧的 IP 出场信息（`continuity_from_previous`）

LLM 返回结构化 JSON，包含该帧的：
- `role`：选择的角色
- `appearance_description`：自然语言描述 IP 在画面中的样子（服装、动作、表情、互动、构图位置和大小）
- `presence_level`：出场规格
- 这个 `appearance_description` 直接作为 IP 身份信息注入最终 image prompt

### 7.3 关键优势

- **场景自适应**：LLM 理解"爱情"和"文旅"需要不同的 IP 出场方式
- **帧间变化**：LLM 理解第 1 帧需要建立场景（IP 全身），第 5 帧需要情感聚焦（IP 半身或不出镜）
- **内容优先**：IP 服务于内容，不是内容迁就 IP
- **自然语言注入**：LLM 输出的自然语言描述比关键词拼接更自然，与 image prompt 的融合更流畅

### 7.4 presence_type 的保留

`IPPresenceType` 枚举（STRONG_IDENTITY / BALANCED_NARRATIVE / SCENE_INTEGRATED / LOW_INTRUSION / SYMBOLIC_ONLY / ABSENT）仍然保留，但由 LLM 决定，不再由确定性规则推断。LLM 可以选择 ABSENT（不出镜）。

## 8. Z-Image Prompt 融合

### 8.1 当前

```
最终 prompt = 场景描述 + ", " + "白色卡通兔子, 古城文旅向导, 亲和好奇的表情, ..." + 负约束
```

IP 关键词被作为逗号分隔的标签拼接，与场景描述的自然语言风格不统一。

### 8.2 目标

```
最终 prompt = 场景描述 + ", " + LLM 生成的 IP 出场描述 + 负约束
```

LLM 生成的 IP 出场描述示例：
- 文旅场景："一只白色卡通兔子站在古城门前，蓝色领结，手持导览旗，温和地指向城门，半身中景"
- 爱情场景："画面边缘的咖啡馆角落，白色兔子的耳朵和蓝色领结隐约可见，如一个安静的陪伴者"
- 美食场景："白色卡通兔子坐在餐桌旁，戴着厨师帽（保持长耳朵和领结可见），好奇地看着食物"

## 10. 测试策略

1. **模型测试**：IPProfile 序列化/反序列化，新字段不丢失
2. **Planner 测试**：不同内容域（爱情/文旅/科技）产生不同的 IP 出场描述
3. **Prompt 测试**：最终 image prompt 中 IP 描述与场景自然融合，不机械拼接
4. **边界测试**：
   - LLM 选择 ABSENT 时 IP 不出现
   - LLM 选择"局部细节"时只有耳朵/领结
   - 多帧间有变化（不是所有帧一样）

## 11. 实施顺序

1. 先改数据模型（IPProfile + preset JSON）
2. 再改 IPUsagePlanner（LLM 驱动的帧级适配）
3. 再改 prompt 融合层（消费 LLM 生成的描述）
4. 最后补测试
