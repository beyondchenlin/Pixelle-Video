# 分镜工作台空状态问题说明

## 问题现象

在 `http://localhost:8501/Storyboard_Workbench` 打开分镜工作台时，如果当前会话还没有在 Home 页面生成过内容，页面只显示提示：

> 先在 Home 生成一次内容，分镜工作台会在这里显示最新分镜。

这会导致用户第一次进入 Workbench 时看不到任何默认结构或空内容示例，需要先完成一次生成才能理解该页面后续会展示和编辑什么内容。

## 用户期望

用户希望分镜工作台在没有真实生成结果时，也能展示一份默认的空内容示例，而不是只显示一条提示语。生成真实内容后，再用真实分镜替换默认示例。

## 当前根因

当前 Workbench 页面完全依赖 `session_state["storyboard_preview_snapshot"]` 中的最近一次分镜快照。

关键逻辑位于：

- `web/pages/3_🧭_Storyboard_Workbench.py`
- `web/state/storyboard_preview.py`
- `web/components/storyboard_preview.py`
- `tests/test_storyboard_workbench_page.py`

页面渲染流程如下：

1. `render_storyboard_workbench_page()` 调用 `get_storyboard_preview_snapshot(...)`。
2. `get_storyboard_preview_snapshot()` 只会从 `session_state["storyboard_preview_snapshot"]` 读取已存在的分镜快照。
3. 如果没有快照，页面会清空 `storyboard_override_draft`。
4. 然后调用 `ui.info(translate("storyboard.workbench.empty_state"))`。
5. 最后直接 `return`，不会调用 `render_storyboard_preview()`。

因此，当前行为不是后端、模型或生成流程限制，而是页面层空状态设计导致的：没有真实快照时，Workbench 被设计成提前返回。

## 现有测试约束

`tests/test_storyboard_workbench_page.py` 中的 `test_storyboard_workbench_page_shows_empty_state_without_snapshot` 明确验证了当前行为：

- 没有 `storyboard_preview_snapshot` 时只显示 `storyboard.workbench.empty_state`。
- 不调用预览渲染器。
- 清空 `storyboard_override_draft`。

如果要改为空示例展示，需要同步调整或替换这个测试。

## 建议修改方案

推荐在页面层处理空状态，保持改动范围最小。

### 方案一：页面层内置示例快照，推荐

当 `preview_snapshot is None` 时：

1. 显示一条提示，说明当前内容是示例，生成后会自动替换。
2. 构造一份只用于展示的内置示例快照。
3. 调用现有 `preview_renderer(...)` 渲染示例。
4. 不解析真实 Workbench client。
5. 不写入 `storyboard_override_draft`。
6. 不启用图片候选、选择、重抽等真实操作。

这种方式的优点：

- 不污染真实会话状态。
- 不伪造一次生成结果。
- 复用现有 `render_storyboard_preview()` 展示结构。
- 真实生成后仍走原有逻辑。

需要注意：示例快照要满足 `build_storyboard_preview_rows()` 的数据合同，例如：

- `storyboard_generation.plan_id`
- `storyboard_generation.revision`
- `storyboard_generation.source_digest`，必须是 64 位十六进制字符串
- `storyboard_generation.frames`
- 顶层 `frames`

### 方案二：在 `render_storyboard_preview()` 内处理空 rows

也可以让 `render_storyboard_preview()` 在 `build_storyboard_preview_rows()` 返回空列表时渲染默认示例。

这种方式不推荐作为首选，因为 `render_storyboard_preview()` 是通用组件，内部处理示例容易影响其他调用场景。

### 方案三：初始化 session_state 时写入假快照

不建议这样做。把示例写进 `session_state["storyboard_preview_snapshot"]` 容易让后续流程误以为已经有真实生成结果，还可能影响字段锁定、覆盖草稿和再次生成参数。

## 建议验收标准

1. 首次打开 Workbench 且未生成内容时，页面显示默认空内容示例。
2. 示例内容有清晰提示，不能让用户误以为已经完成真实生成。
3. 示例状态不写入 `storyboard_override_draft`。
4. 示例状态不触发图片候选、选择、重抽等真实 Workbench 操作。
5. 在 Home 生成真实内容后，Workbench 显示真实最新分镜，原有字段锁定和候选图逻辑保持不变。
6. 更新 `tests/test_storyboard_workbench_page.py`，覆盖无快照时渲染示例的行为。
