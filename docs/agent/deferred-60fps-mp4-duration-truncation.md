# 六十帧静态画面视频的封装时长截短

## 状态

- 记录日期：2026-08-13
- 状态：经用户明确决定延期，本次超帧运行环境修复不包含该改动
- 影响路径：`pixelle_video/services/video_operations.py` 中的 `VideoService.create_video_from_image`

## 已验证现象

使用四万八千赫兹音频生成六十帧每秒的静态画面视频时，输入音频时长为 `2.883313` 秒，输出封装时长为 `2.883008` 秒，尾部缩短 `0.000305` 秒。相同素材使用三十帧每秒时没有出现截短。

二万四千赫兹音频的六十帧复现同样会缩短约 `0.000284` 秒，因此问题由高帧率与封装时间基组合触发，不是某一个音频文件损坏。

## 根因

当前实现已经把画面帧数和音频补齐到同一个目标时长，但写入 MP4 容器时没有指定能够同时表达视频帧边界和音频采样边界的电影时间基。容器默认时间基无法精确表示部分六十帧与采样率组合，复用编辑列表时会把尾部向前取整。

## 后续修复边界

后续独立改动应只处理容器时间基，不改变本次超帧依赖、模板路由或部署行为：

1. 从音频探测结果读取采样率。
2. 对 MP4、M4V 和 MOV 输出使用帧率与采样率的最小公倍数作为电影时间基。
3. 对无效采样率和超出容器整数范围的时间基明确失败。
4. 增加三十帧与六十帧、二万四千与四万八千赫兹的真实封装回归测试。
5. 验收要求是输出不能短于输入音频，且输出时长仍落在一个视频帧以内。

本记录只保留已经复现的事实和独立修复边界，不在本次改动中夹带实现。
