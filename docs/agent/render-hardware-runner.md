# 视频硬件认证构建机接入规范

## 1. 目的与完成边界

本规范用于接入真实硬件构建机，为以下三种产品支持的编码器生成最终视频、成品探针和可聚合的主机证据：

- `h264_nvenc`：英伟达硬件编码器。
- `h264_qsv`：英特尔快速同步编码器。
- `h264_vaapi`：视频加速接口编码器。

单元测试、软件模拟、仅列出编码器名称或者硬件初始化失败后的软件回退，都不能代替真实设备证据。只有同一次远程自动化运行中的三份精确编码器主机报告全部通过，并且 `hardware_certification_report.json` 聚合报告通过，才代表硬件发布认证完成。

当前英伟达设备可以承担第一类认证。英特尔核显的 Linux 主机可以承担快速同步和视频加速接口两类认证，但单作业一次性构建机只能领取一个作业；同一物理主机必须依次启动两个独立的一次性实例，并在两次作业之间恢复干净镜像。

## 2. 信任边界

仓库为公共仓库，自托管构建机必须视为会执行仓库代码的高权限设备。接入时必须同时满足：

1. 使用单作业一次性注册的虚拟机或隔离实例，并在任务后销毁虚拟机或恢复系统镜像；持久构建服务不符合本规范。
2. 不保存个人文件、生产数据、长期访问令牌、云凭证、签名密钥或其他仓库工作区。
3. 只允许 `dev` 和 `main` 分支人工触发 `.github/workflows/render-hardware-certification.yml`。
4. 仓库配置受保护环境 `render-hardware-certification`，设置必要评审人和分支限制。
5. 组织仓库必须用构建机组限制到本仓库及本工作流；个人仓库没有该边界时，只能在受保护环境批准后为本次运行注册单作业一次性构建机。禁止向拉取请求和任意任务分支开放。
6. 每次运行后销毁工作目录和临时目录；不得复用上一次运行生成的证据。
7. 检出步骤不得持久化仓库写入凭证，构建机账号不具备推送权限。

缺少任一条件时不得把该机器注册为硬件发布认证构建机。

## 3. 机器与驱动要求

### 3.1 通用要求

- 六十四位操作系统和 Python 3.11。
- 仓库锁定依赖能够通过 `uv sync --frozen --extra dev` 安装。
- `ffmpeg -hide_banner -version` 可以执行。
- 音视频工具实际包含目标编码器，且一帧真实编码探测成功。
- 系统时间和网络正常，以便远程自动化服务校验同一次运行的身份。
- 运行账号可以读写独立临时目录，但没有仓库外不必要的权限。

### 3.2 英伟达构建机

- 安装与显卡匹配的英伟达驱动。
- `nvidia-smi` 能识别目标显卡。
- 音视频工具的 `h264_nvenc` 一帧真实编码成功。
- 构建机标签同时包含 `self-hosted`、`render-hardware`、`render-h264-nvenc`。

### 3.3 英特尔媒体构建机

- 使用带启用核显和媒体引擎的英特尔处理器；固件中不得关闭核显。
- 使用 Linux，内核必须暴露字符设备 `/dev/dri/renderD128`。
- 安装与处理器代际匹配的英特尔媒体驱动，以及同时包含 `h264_qsv` 和 `h264_vaapi` 的音视频工具。
- 运行账号必须具备 `/dev/dri/renderD128` 的读写权限；通过设备组授权，禁止用管理员账号运行构建服务。
- 快速同步作业标签同时包含 `self-hosted`、`render-hardware`、`render-h264-qsv`。
- 视频加速接口作业标签同时包含 `self-hosted`、`render-hardware`、`render-h264-vaapi`。

英特尔物理主机上的两个一次性实例分别使用最后两组精确设备标签。自动化矩阵会固定设置：

```text
PIXELLE_FFMPEG_QSV_DEVICE=/dev/dri/renderD128
PIXELLE_FFMPEG_VAAPI_DEVICE=/dev/dri/renderD128
```

应用的快速同步与视频加速接口探测命令、正式渲染命令都会读取同一设备设置。设备路径必须是 `/dev/dri/renderD<number>` 形式并解析到字符设备；普通文件、任意路径和不存在的设备会被拒绝。

## 4. 注册前本机验收

在机器注册到远程仓库前，从待认证提交的干净工作树依次执行：

```sh
uv sync --frozen --extra dev
uv run python scripts/run_render_qualification.py hardware --hardware-codec h264_qsv --output-root /tmp/pixelle-h264-qsv
uv run python scripts/run_render_qualification.py hardware --hardware-codec h264_vaapi --output-root /tmp/pixelle-h264-vaapi
```

英伟达构建机把编码器参数分别替换为 `h264_nvenc`。每个输出目录必须同时存在：

- `hardware_report.json`，其中精确要求的编码器结果为通过。
- `hardware/*.mp4`，真实最终视频存在且大小非零。
- `hardware/*.render_probe.json`，探针声明的实际编码器与要求一致。
- 报告中的提交散列与当前提交完全一致，工作树状态为干净。

任何一步失败都先修复驱动、权限、设备路径或音视频工具构建，不得通过删除精确编码器要求、允许软件回退或手工修改报告绕过。

## 5. 远程仓库接入顺序

1. 在仓库设置中创建受保护环境 `render-hardware-certification`，添加必要评审人，并限制为 `dev` 与 `main` 分支。
2. 组织仓库创建仅供本仓库及该认证工作流使用的自托管构建机组；个人仓库跳过构建机组，但必须保留后续的一次性注册约束。
3. 先触发工作流并完成受保护环境批准，再按远程仓库生成的一次性注册命令安装构建服务，注册时加入 `--ephemeral` 单作业一次性参数；不把注册令牌写入仓库、日志或文档。
4. 添加本规范第三节要求的通用标签和精确设备标签。
5. 确认构建服务账号没有仓库写入权限，也没有个人或生产凭证。
6. 在 `dev` 分支人工触发“视频硬件认证”工作流，并由受保护环境评审人批准。
7. 下载聚合制品，确认 `hardware_certification_report.json` 为通过，再允许该提交取得硬件发布资格。
8. 每个构建机处理一个作业后必须自动注销；随后销毁虚拟机或恢复系统镜像。快速同步和视频加速接口共用物理主机时，恢复镜像后再注册第二个一次性实例。

## 6. 失败处理

- 作业持续排队：精确设备标签没有对应的在线构建机，检查构建服务和标签拼写。
- 快速同步设备不可用：检查核显是否启用、媒体驱动、`/dev/dri/renderD128` 和运行账号设备组权限。
- 视频加速接口上传失败：检查设备权限和驱动，禁止去掉硬件帧上传步骤。
- 实际编码器变成软件编码器：该次认证失败，保留报告定位原因，禁止接受回退产物。
- 聚合报告拒绝证据：检查三个作业是否来自同一提交、同一次运行、干净工作树和唯一设备身份，禁止跨运行拼接历史制品。
- 报告缺失：上传步骤仍会运行，但聚合作业必须失败关闭；修复上游真实渲染失败后重新执行整次认证。
