# 视觉签名身份与场景渲染合同

## 固定事实

- 身份名称只用于元数据，不自动成为画面文字。
- 核心特征、辅助特征、固定配色、特征布局和禁止变化项必须来自资产档案，并共同进入身份摘要。
- `visible_text_whitelist` 是整幅画唯一允许出现的文字；列表为空时画面无文字。
- `image_text_palette` 只定义已授权文字出现时的字形与配色，不创造新的文字内容。

## 场景适配

- 视觉签名固定身份事实不变。
- 线条、材质、真实程度、透视和光影跟随当前场景。
- 只有原分镜明确把视觉身份写成参与事件的主体时，视觉身份才按剧情主体设计；其余画面中，视觉身份固定作为系列识别标记，以静态附着关系进入场景。
- 系列识别标记优先由当前场景中同时服务文案表达或整体构图的已有物体承接。当前场景没有合适物体时，可以创作一个同时服务文案含义、场景用途和整体构图的新物体；移除视觉身份后，该物体仍须是画面中合理且有作用的组成部分。
- 视觉签名通过承接物的表面图形、浮雕、材质纹理或局部造型呈现，并与承接物共同构成同一个物体。承接物及其视觉签名必须具有一致的附着、材质、边界、透视和光照关系。
- 标准强调保持次级可辨；增强强调保持主体优先，同时无需寻找即可识别。

## 三阶段边界

1. 内容生成：只处理分镜事实，不接触视觉签名。
2. 融合草稿：加入固定身份、承载关系、场景渲染与文字授权。
3. 最终审查重写：原始文本直接成为图片正向提示词。

每个阶段每帧只调用一次大模型。模型输出后，本地不解析、不判断、不修复、不改写、不重试；图片每帧只生成一次，生成后不自动审查或重生成。

## 参考图

工作流支持参考图时，已校验的参考资源与文字身份档案共同约束首次生成；不支持时只使用完整身份档案。首次请求审计必须记录身份摘要、参考资源、提示词、工作流版本、随机种子和实际执行参数。
