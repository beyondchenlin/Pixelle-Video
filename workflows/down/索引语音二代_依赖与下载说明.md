# 索引语音二代依赖与下载说明

## 1. 对应工作流

- 工作流路径：`workflows/selfhost/tts_index2.json`
- 工作流用途：在本地 ComfyUI 中调用 `ComfyUI-Index-TTS` 的 `IndexTTS2BaseNode` 生成语音，并通过 `SaveAudio` 保存为 FLAC 音频。
- 当前工作流关键节点：
  - `PrimitiveStringMultiline`
  - `VHS_LoadAudioUpload`
  - `IndexTTS2BaseNode`
  - `IndexTTS2CacheControlNode`
  - `SaveAudio`

当前工作流使用内置 `SaveAudio` 保存节点，输出为 FLAC 无损音频。

## 3. 目录职责划分

这次最容易混淆的是“程序目录”“运行时目录”“项目目录”三者不是一回事。

### 3.1 ComfyUI 程序目录

- 路径：`E:\comfyui`
- 主要存放：
  - `ComfyUI.exe`
  - `resources\ComfyUI`
  - `comfyui\models`
  - `comfyui\custom_nodes`

### 3.2 ComfyUI 运行时目录

- 路径：`E:\comfyui-venv`
- 主要存放：
  - `.venv`
  - `input`
  - `output`
  - `user`

- 路径：本仓库根目录
- 项目自己的 `.venv` 仅供 Pixelle 项目代码使用，不等于 ComfyUI 的运行环境。

## 6. 本次安装过程中真正踩到的坑

### 6.1 把包装进了错误的虚拟环境

现象：

- 项目 `.venv` 里装了包，但 ComfyUI 依然报缺依赖。

原因：

- ComfyUI Desktop 使用的是它自己的运行时 `.venv`，不是 Pixelle 项目的 `.venv`。

处理：

- 所有安装命令都显式写成：

```powershell
E:\comfyui\resources\uv\win\uv.exe pip install --python E:\comfyui-venv\.venv\Scripts\python.exe <包名>
```

### 6.2 ComfyUI Desktop 自愈逻辑想把环境重建回 Python 3.12

现象：

- Maintenance 页面提示重新安装 Python packages。
- 后台出现 `uv venv --python 3.12 --python-preference only-managed`。

原因：

- ComfyUI Desktop 的默认自愈逻辑偏向托管的 `Python 3.12`。
- 但这台机器为了兼容 `IndexTTS-2 + DeepSpeed + Windows`，实际运行时固定在 `Python 3.11`。

处理：

- 不要让 Desktop 覆盖现有 `.venv`。
- 当前机器已经把运行时固定到 `E:\comfyui-venv\.venv`。

### 6.3 Desktop 启动配置文件 BOM 导致客户端打不开

现象：

- `ComfyUI.exe` 点击后无法正常打开。

原因：

- `config.json` 被写成了带 BOM 的 UTF-8。
- Desktop 读取 JSON 时被 BOM 绊倒。

处理：

- 配置文件改为无 BOM UTF-8。

结论：

- 以后如果脚本要写 `%APPDATA%\ComfyUI\config.json`，必须确保写出的 JSON 不带 BOM。

### 6.4 `torch` 元数据损坏导致 Maintenance 误报

现象：

- Maintenance 页面提示 Python packages 缺失。

原因：

- `torch-2.10.0+cu130.dist-info` 曾经变成空目录。

处理：

- 重新安装同版本 `torch` 后恢复。

### 6.5 DeepSpeed 已安装但未真正启用

现象：

- 即使安装了 `deepspeed`，日志里仍可能回退到标准推理。

原因：

- `infer_v2.py` 原逻辑在成功导入 `deepspeed` 后，没有把 `use_deepspeed` 正确置回 `True`。

处理：

- 已在本机对应文件里补过启用逻辑。

### 6.6 DeepSpeed Windows wheel 缺少推理 op

现象：

- 报 `pt_binding.cpp` 缺失等错误。

原因：

- 普通安装得到的 wheel 不一定带 `transformer_inference` 编译产物。

处理：

- 本机实际使用的是带 `transformer_inference` 的 DeepSpeed wheel。

### 6.7 `transformers 5.5.4` 与当前链路不兼容

现象：

- 出现过以下错误：
  - `AttributeError: 'DynamicCache' object has no attribute 'dtype'`
  - `AttributeError: 'GPT2Config' object has no attribute 'pruned_heads'`

原因：

- `transformers 5.x` 的 GPT2 cache/config 路径和当前 `ComfyUI-Index-TTS + DeepSpeed` 组合不兼容。

处理：

- 当前机器已回退到 `transformers==4.51.0`，并验证可正常生成音频。

### 7.2 Pixelle 显存释放端点

`ComfyUI-Index-TTS` 会把 IndexTTS2 模型保存在插件自己的全局 loader/cache 中，ComfyUI 标准 `/free` 只管理 ComfyUI model manager 里的模型，不能直接释放这部分私有缓存。因此 Pixelle 通过补丁脚本安装 `POST /pixelle/indextts2/free` 端点，从源头补齐插件释放契约。

验证端点文件已安装：

```powershell
Test-Path E:\ComfyUIData\custom_nodes\ComfyUI-Index-TTS\pixelle_routes.py
Select-String -Path E:\ComfyUIData\custom_nodes\ComfyUI-Index-TTS\pixelle_routes.py -Pattern "/pixelle/indextts2/free"
```

补丁后需要重启 ComfyUI。重启后可验证 HTTP 端点：

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8188/pixelle/indextts2/free
```

Pixelle 配置 `model_cleanup_mode: comfyui_and_extensions` 时，会先调用 ComfyUI `/free`，再调用 `/pixelle/indextts2/free`。这和 z-image 这类标准模型的释放逻辑保持同一入口，但额外覆盖 IndexTTS2 插件私有缓存。工作流中的 `keep_models_cached = true` 仍然保留，用于同一批次内复用模型；释放发生在强制清理、OOM 恢复或 IndexTTS2 session 退出阶段。

如果重装或更新 `ComfyUI-Index-TTS`，应先重新运行上述脚本，再启动工作流验证。不要只依赖一次性的手工改动。
