# 索引语音二代依赖与下载说明

## 1. 对应工作流

- 工作流路径：`workflows/selfhost/tts_index2.json`
- 工作流用途：在本地 ComfyUI 中调用 `ComfyUI-Index-TTS` 的 `IndexTTS2BaseNode` 生成语音，并导出 MP3。
- 当前工作流关键节点：
  - `PrimitiveStringMultiline`
  - `VHS_LoadAudioUpload`
  - `IndexTTS2BaseNode`
  - `IndexTTS2CacheControlNode`
  - `SaveAudio`

当前工作流使用内置 `SaveAudio` 保存节点，输出为 FLAC 无损音频。

以下组合已经在本机实际跑通过 `IndexTTS-2 + ComfyUI + GPU + DeepSpeed`：

- ComfyUI 运行时目录：`E:\comfyui-venv`
- ComfyUI 实际 Python：`E:\comfyui-venv\.venv\Scripts\python.exe`
- Python：`3.11.9`

- Torchaudio：`2.10.0+cu130`

- Accelerate：`1.13.0`

## 3. 目录职责划分

这次最容易混淆的是“程序目录”“运行时目录”“项目目录”三者不是一回事。

### 3.1 ComfyUI 程序目录

- 路径：`E:\comfyui`
- 主要存放：
  - `ComfyUI.exe`
  - `resources\ComfyUI`
  - `comfyui\models`
  - `comfyui\custom_nodes`

### 3.2 ComfyUI 运行时目录

- 路径：`E:\comfyui-venv`
- 主要存放：
  - `.venv`
  - `input`
  - `output`
  - `user`

### 3.3 Pixelle 项目目录

- 路径：本仓库根目录
- 项目自己的 `.venv` 仅供 Pixelle 项目代码使用，不等于 ComfyUI 的运行环境。

结论：

- 不要把 `deepspeed`、`transformers`、`tokenizers` 等运行时依赖装到 Pixelle 项目的 `.venv` 里。
- 一切以 ComfyUI 启动日志里的 `** Python executable:` 为准。

## 4. 配置文件分别负责什么

### 4.1 ComfyUI Desktop 配置

- 路径：`%APPDATA%\ComfyUI\config.json`
- 当前关键值：
  - `basePath = E:\comfyui-venv`
  - `selectedDevice = nvidia`

它决定的是 ComfyUI Desktop 运行时用哪个目录，不负责 Pixelle 的业务配置。

### 4.2 ComfyUI-Manager 配置

- 路径：`E:\comfyui-venv\user\__manager\config.ini`
- 当前关键值：
  - `network_mode = public`

说明：

- 这会导致日志里偶尔出现 `Cannot connect to comfyregistry`。
- 这是非阻塞问题，不影响本地 TTS 推理。
- 如果后续只想安静使用本地环境，可改成 `offline`。

### 4.3 Pixelle 项目配置

- 路径：`config.yaml`

说明：

- 它负责项目业务配置，不负责给 ComfyUI 安装 Python、CUDA、DeepSpeed。
- 如果遇到 ComfyUI 运行时问题，优先检查的不是这里。

## 6. 本次安装过程中真正踩到的坑

### 6.1 把包装进了错误的虚拟环境

现象：

- 项目 `.venv` 里装了包，但 ComfyUI 依然报缺依赖。

原因：

- ComfyUI Desktop 使用的是它自己的运行时 `.venv`，不是 Pixelle 项目的 `.venv`。

处理：

- 所有安装命令都显式写成：

```powershell
E:\comfyui\resources\uv\win\uv.exe pip install --python E:\comfyui-venv\.venv\Scripts\python.exe <包名>
```

### 6.2 ComfyUI Desktop 自愈逻辑想把环境重建回 Python 3.12

现象：

- Maintenance 页面提示重新安装 Python packages。
- 后台出现 `uv venv --python 3.12 --python-preference only-managed`。

原因：

- ComfyUI Desktop 的默认自愈逻辑偏向托管的 `Python 3.12`。
- 但这台机器为了兼容 `IndexTTS-2 + DeepSpeed + Windows`，实际运行时固定在 `Python 3.11`。

处理：

- 不要让 Desktop 覆盖现有 `.venv`。
- 当前机器已经把运行时固定到 `E:\comfyui-venv\.venv`。

### 6.3 Desktop 启动配置文件 BOM 导致客户端打不开

现象：

- `ComfyUI.exe` 点击后无法正常打开。

原因：

- `config.json` 被写成了带 BOM 的 UTF-8。
- Desktop 读取 JSON 时被 BOM 绊倒。

处理：

- 配置文件改为无 BOM UTF-8。

结论：

- 以后如果脚本要写 `%APPDATA%\ComfyUI\config.json`，必须确保写出的 JSON 不带 BOM。

### 6.4 `torch` 元数据损坏导致 Maintenance 误报

现象：

- Maintenance 页面提示 Python packages 缺失。

原因：

- `torch-2.10.0+cu130.dist-info` 曾经变成空目录。

处理：

- 重新安装同版本 `torch` 后恢复。

### 6.5 DeepSpeed 已安装但未真正启用

现象：

- 即使安装了 `deepspeed`，日志里仍可能回退到标准推理。

原因：

- `infer_v2.py` 原逻辑在成功导入 `deepspeed` 后，没有把 `use_deepspeed` 正确置回 `True`。

处理：

- 已在本机对应文件里补过启用逻辑。

### 6.6 DeepSpeed Windows wheel 缺少推理 op

现象：

- 报 `pt_binding.cpp` 缺失等错误。

原因：

- 普通安装得到的 wheel 不一定带 `transformer_inference` 编译产物。

处理：

- 本机实际使用的是带 `transformer_inference` 的 DeepSpeed wheel。

### 6.7 `transformers 5.5.4` 与当前链路不兼容

现象：

- 出现过以下错误：
  - `AttributeError: 'DynamicCache' object has no attribute 'dtype'`
  - `AttributeError: 'GPT2Config' object has no attribute 'pruned_heads'`

原因：

- `transformers 5.x` 的 GPT2 cache/config 路径和当前 `ComfyUI-Index-TTS + DeepSpeed` 组合不兼容。

处理：

- 当前机器已回退到 `transformers==4.51.0`，并验证可正常生成音频。

## 7. 当前机器额外做过的本地兼容补丁

以下补丁不在本仓库内，而是在 ComfyUI 运行环境或插件目录里手工修改过。后续如果重装插件、重装 DeepSpeed 或重建运行时，需要注意这些补丁可能会丢失。

### 7.1 ComfyUI-Index-TTS 补丁

- `E:\comfyui\comfyui\custom_nodes\ComfyUI-Index-TTS\indextts2\vendor\indextts\infer_v2.py`
  - 成功导入 `deepspeed` 后显式启用 `use_deepspeed`

- `E:\comfyui\comfyui\custom_nodes\ComfyUI-Index-TTS\indextts2\vendor\indextts\gpt\model_v2.py`
- `E:\comfyui\comfyui\custom_nodes\ComfyUI-Index-TTS\indextts2\vendor\indextts\gpt\model.py`
  - `build_hf_gpt_transformer()` 改为使用插件 vendored 的 `GPT2Model`
  - 目的：避免新版 `transformers` 的 GPT2/Cache 路径直接撞上 DeepSpeed 老推理接口

### 7.2 DeepSpeed 运行时补丁

- `E:\comfyui-venv\.venv\Lib\site-packages\deepspeed\runtime\compiler.py`
  - `torch.compile` 失败时安全回退

- `E:\comfyui-venv\.venv\Lib\site-packages\deepspeed\runtime\zero\muon\muon_optimizer.py`
  - 修正导入兼容问题，避免无关模块在导入阶段把 DeepSpeed 拖死

结论：

- 如果后续更新 `ComfyUI-Index-TTS` 或重新安装 `deepspeed`，出现“以前能跑、现在突然又不行”，优先回看这里。

## 8. 运行工作流时的配置注意事项

### 8.1 参考音频路径

当前工作流 `workflows/selfhost/tts_index2.json` 使用：

- `VHS_LoadAudioUpload.audio = ref_audio.wav`

注意：

- 运行时的输入目录现在是 `E:\comfyui-venv\input`
- 因此默认参考音频应放在：
  - `E:\comfyui-venv\input\ref_audio.wav`

### 8.2 模型缓存

当前工作流已经接入：

- `IndexTTS2CacheControlNode.keep_models_cached = true`

作用：

- 避免每次都完整重载 `IndexTTS-2` 全套模型
- 连续生成时会明显更快

### 8.3 `triton` 缺失提示

当前日志里会看到：

- `Found comfy_kitchen backend triton: unavailable`

说明：

- 这是可选后端，不影响当前 `IndexTTS-2` 主链路。
- 不建议为了消掉这条提示，在 Windows 主环境里硬装第三方 Triton 分支。

## 10. 成功运行时应该看到什么

一条成功的 `IndexTTS-2` 日志，至少应包含这些信号：

- 没有 traceback
- 没有 `DeepSpeed加载失败`
- 能看到模型加载日志
- 能看到 `>> start inference...`
- 最后出现：
  - `>> Total inference time: ...`
  - `>> Generated audio length: ...`
  - `Prompt executed in ... seconds`

## 11. 下次排障时的优先检查顺序

1. 先确认 ComfyUI 实际 Python 还是不是 `E:\comfyui-venv\.venv\Scripts\python.exe`
2. 再确认 `transformers` 是否还是 `4.51.0`
3. 再确认 `ref_audio.wav` 是否在 `E:\comfyui-venv\input`
4. 再确认插件目录和模型目录没有被覆盖
5. 如果是重装后突然失效，再检查第 7 节列出的本地兼容补丁是否还在
